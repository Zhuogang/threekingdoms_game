# Track 05：地图、战场渲染与交互

> **Historical design / planning record, retained October 22, 2026.** Statements such as “pending” describe this document’s original implementation stage. Read the [current v0.3 overview](../../README.md), [current status](../../implementation-status.md) and [player guide](../../player-guide.md) for the playable version. This record does not create new implementation work.

**状态（2026-10-21）：主地图与 24×20 战场的相机、fit/focus、战场小地图、队伍/状态图层、键盘交互和双语标签已接入。第 10 节是早期候选的预修复审计；当前交付和剩余门槛见第 11 节与[实施台账](../../implementation-status.md)。200% 缩放、大字号和低端设备检查仍需玩家验收。**

**负责人：渲染与地图 UI 代理。**

**定位：** 为新的三国策略游戏实现地理可信的主地图，以及中式水墨、斜俯视的 24×20 战场。复用可维护的技术和原创资产，不以恢复 BAYE 行为作为验收标准。

本轨道与 [04：战场和水战](04-battlefields-and-water-combat.md)、[06：imagegen 与美术](06-imagegen-and-artwork.md) 分开执行。04 决定哪里可走、伤害和胜负；05 显示状态并把操作转换为命令；06 提供可替换的画作和素材。显示与规则不各自维护一份地形。

## 1. 已确定的范围

- 战场为 24×20 逻辑方格，长宽各为 v0.2 的两倍，面积四倍。
- 保留中式水墨画；采用高视角斜俯视地面与立体地物，以空间层次、阅读和操作为重点。
- 所有作战单位均可下水，不以水军技能或兵种为前提；水中攻击和防御均降低，岸上单位可按通常射程攻击水上单位。具体公式、移动费用和伤害适用范围以 04 为唯一规则来源。
- 没有攻城系统：战场不实现城墙、城门耐久、攀城、攻城器、破门或市街战。主地图仍可使用古城城楼轮廓，它是城市标志，不代表战斗设施。
- v0.3 不要求兼容旧存档。规则集标识为 `hegemony-3`，本地存储命名空间为 `hegemony-v0.3`，以 [共同合同](00-decisions-and-contracts.md) 为准；不得为旧 12×10 地图增加双渲染模式拖延本轨道。

## 3. 跨轨道视觉合同 V1

本合同是未来实现的共同起点；不是本次已经生成的文件。若集成中需要改变投影、锚点或单位占位，必须先更新合同版本并告知 04/06，不能在各轨道自行修正。

### 3.1 逻辑格与地面投影

- 战场逻辑坐标保持整数 `(x,y)`，范围分别为 `0..23`、`0..19`；逻辑邻接、射程与通行都由 04 计算。
- 默认地面菱形宽 128、高 64 世界单位，采用 **2:1 斜俯视投影**，不宣称是严格等角几何。
- 以格子中心为参考：`worldX=(x-y)×64`，`worldY=(x+y)×32`，然后叠加视图原点。所有投影和逆变换使用同一模块。
- 逆变换先去掉镜头平移/缩放与视图原点，再求连续网格坐标，最后做实际菱形命中与边界裁定。固定边界归属顺序，避免共享边上一会选左格一会选右格。
- 地图外框从四个极端格子的完整菱形顶点求包围盒，再增加地物突出与标签边距；不能继续用旧 `1000×720` 居中公式计算战场。
- 山体高低是表现高度；没有规则层支持时，不从画面高低推断射程、视线、伤害或通行。
- `hill` 是可通行山坡，`cliff` 是全部兵种均不可进入的峭壁。两者必须有不同轮廓、原生不可通行标记和悬浮说明；不可仅把同一石岭图片调深一点后要求玩家猜测。画面高度本身仍不是通行判据。

### 3.2 素材与坐标约定

| 类型                       | 建议交付尺寸 | 锚点（归一化） | 使用方式                                                       |
| -------------------------- | ------------ | -------------- | -------------------------------------------------------------- |
| 地表材质                   | 512×512      | 无立体脚点     | 采样到地面并按实际地形遮罩裁切；不把生成图里的轮廓当作规则边界 |
| 山林/营地地物              | 512×512 RGBA | `(0.5,0.84)`   | 锚点落在格中心；占地与最大外扩从清单读取                       |
| 单位图                     | 256×256 RGBA | `(0.5,0.86)`   | 脚点落在单位格中心；姿态与兵种徽记分层                         |
| 通用运输载具标记           | 256×128 RGBA | `(0.5,0.60)`   | 水面上的运输小舟/平台轮廓，与兵种徽记组合                      |
| 水上、行动、阵营等 UI 徽记 | 原生图形优先 | 屏幕坐标对齐   | 不能依赖生成图片中的文字、颜色或形状决定状态                   |

PNG/无损源图用于归档，运行时以优化 WebP 为主。允许生成源图尺寸不同，归一化输出必须符合合同且不切掉武器、马匹或底座。名义图像尺寸与实际绘制宽高分开记录；不能通过不受控裁边改变脚点。

2:1 投影、地物脚点和像素尺寸是约定参数，并非用户要求的历史事实。正式批量产图前，用一张地形和一名单位在实际镜头中验证；验证后同时冻结 05/06 的清单版本。

## 4. 主地图工作包

### 4.1 地理位置与画作

1. 从 01 的地理锚点生成显示位置；城市真实锚点与图标/标签偏移分开。标签碰撞处理不能改变距离计算。
2. 绘制经批准的路线折线、河流主干、山系和地理方向。图形仅用于呈现；所有里程、预计到达和路线合法性由 01/02 查询。
3. 最终水墨背景必须使用同一份地理布局参考。先用程序绘制的简洁地理底图联调，不等待画作。
4. 延续城市规模差异：洛阳、长安较宏大，邺较繁复，平原较朴素；保持这属于城市视觉身份，而非未经规则支持的实时财富数值。
5. 地理图只承诺经来源核实的地理关系；现代/古代位置不确定的城市、河道按 01 的置信标记呈现说明，不把生图结果当作校准证据。

### 4.2 在途队伍与路线

- 可选中军队/运输队，看到来源、目的地、已行/剩余天数、ETA、粮食和命令状态。
- 位置由行程分段进度映射到路线，不按屏幕两城直线匀速动画。看地图、换语言或重绘不推进战略日。
- 同一路线多队伍采用聚合标记和展开列表，避免旗帜重叠；军队与运输用不同图形，而不是只依赖颜色。
- 选择出征路线时高亮批准路径，显示陆路/山路/水运等种类，以及预计行程的修正原因。
- 同盟、未知情报和敌方队伍可见性遵守规则查询，地图不能泄露仍处于情报迷雾中的精确军力。
- 直辖/太守自治标识和订单状态只读来自治理轨道；点击可以导航到对应面板，但不执行隐藏的内政动作。

## 5. 战场工作包

### 5.1 图层与遮挡

建议层次：底色/材质 → 水体与岸线 → 道路/地面细节 → 地物/单位按脚点排序 → 战术轮廓 → 屏幕标签与提示 → 非阻塞特效。

- 地物和单位按投影脚点的纵向位置排序，稳定 ID 决定并列；不依赖创建顺序。
- 脚点不是图片包围盒底边。马腿、树根、旗帜等透明留白不会影响位置。
- 被山林遮挡的单位显示清楚的轮廓或临时降低前景地物透明度；仍须可以选择与查看。
- 水面、岸线、渡口显示由实际地形邻接导出，不能让画上的河比规则中的水多出一格。
- 草地、农田、道路若没有特殊规则，用同一底层地形查询说明，不用美术暗示未实现的速度或恢复加成。
- 野战营地允许有帐篷/旗帜，不能以城门墙体代替营地而暗示攻城系统。营地是目标覆盖层，沿用真实底层地形的移动与伤害；帐篷/营地身份不提供额外防御，不显示旧版 `fort` 减伤提示。

### 5.2 统一水上状态

**水上状态是位置状态，不是兵种。** 六类现有兵种和未来采用同合同的兵种，落在水格时使用统一状态入口。

1. 单位脚下显示轻型运输载具/水纹与“水上 / Afloat”徽记。骑兵应读成“乘载具过水”，不能画成马匹凭空站在水面或游泳溺水。
2. 中远景用通用舟形加兵种徽记；近景可显示缩小的兵种轮廓。不能因有舟形就把单位换成水军属性。
3. 面板显示规则查询返回的水上攻击/防御修正、原兵种、射程及预计伤害。具体乘数引用 04，不在渲染器或图片上硬编码。
4. 岸上选择单位时，处于通常射程内的水上敌人应显示可攻击标记；水上选择单位时也读取同一规则查询。
5. 进入水格/上岸后标记与预览立即更新；播放移动动画不先改变判定格，也不延迟命令完成后的真实状态。
6. 己方/敌方、被选中/可攻击/不可攻击、正常/混乱等状态要能同时辨认，颜色之外保留形状和文字提示。

### 5.3 大地图镜头与阅读

- 初始镜头使用可读的战术局部视角，而不是强制把 480 格和所有姓名挤入窗口。
- 提供“全图”“所选单位”“双方营地”定位；切换目标后不无条件重置用户缩放。
- 细节视角对单位实际屏幕包围盒及交互目标检查，目标约 40 CSS 像素以上；菱形窄轴不必被夸大为每个方向都 40 像素，但不能出现无法点击的薄条。
- 全图视角使用简化单位/兵种标记，姓名与详细兵力由侧栏承接；放大后逐步恢复细节。
- 缩放围绕指针或触点，拖动不会被判为攻击点击。只在确认的点击落点提交命令。
- 键盘/触控平移可用；手机不依赖鼠标移到边缘。全图之外的移动可通过小地图和“所选单位”键恢复。
- 打开 Wiki、切换语言或字号时保留选择、镜头与未完成命令；地图缩放不与浏览器文字缩放混淆。

### 5.4 小地图

小地图可采用简化俯视方格投影，以提高辨认；不必复制斜俯视细节。必须显示主水体、可通行陆地、不可通行峭壁、营地、敌我单位和当前主视图覆盖区域。

- 小地图点击/拖动转换到同一逻辑格中心，再调用主镜头定位。
- 主镜头框不简单假设为俯视矩形；从屏幕角点逆投影形成范围，再裁到战场内。
- 只有实际可见的敌人/目标才能出现在小地图；图例说明图标含义。
- 可收起/移动，不能遮挡提交行动、结束战斗日或关键提示。

## 6. 规则查询与展示合同

04 至少提供：地图尺寸与地形、单位实际位置、当前位置是否为水、可达格/路径/移动费用、目标合法性与理由、伤害预览分解、状态及营地位置。02 提供当前日期、在途实体和 ETA；01 提供显示路线与城市锚点。

05 只把这些数据转换成图形；不得自行：

- 根据图片是否蓝色判定水格；
- 根据投影像素距离判定射程或路线里程；
- 把舟形当作取得免疫、提高攻击或水军技能的条件；
- 用动画完成回调推进战略日期或扣除粮草；
- 在地图上隐藏不允许的按钮，却仍直接修改城市资源。

展示夹具与正式查询适配器分开，发布构建不得混入可直接改写游戏状态的演示按钮。

## 8. 验收与证据

### 几何与规则一致性

- 对全部 480 个格中心、边界和缩放/平移组合测试正逆变换，外部点击不生成非法命令。
- 选择边缘格、河岸相邻格、地物后单位和两个重叠图片的单位时，命中与规则坐标一致。
- 山坡可走、峭壁不可走的显示与 04 查询一致；不因岩石图片的外扩范围扩大不可通行区域。营地标签准确表达目标身份，不制造额外地形或防御。
- 全兵种进入水格、上岸后，单位徽记和预览与 04 查询一致；水面不改变兵种 ID。
- 选择、拖动、语言切换、缩放和 Wiki 开关不会改变 RNG、日期、资源或存档中的战斗状态。
- 无城墙耐久、破门、登城或市街战入口；城市符号与战场设施在界面上明确分开。

### 阅读与可访问性

- 1366×768、1920×1080、390 宽；中文/英文；正常/大字号与 200% 浏览器缩放。
- 近景能分辨步兵/弓兵/骑兵和其他类型徽记；全图能区分敌我、营地、水体和选中单位。
- 键盘可定位和查看单位；点击失败有原因。移动/攻击区不用颜色作为唯一编码。
- 不被小地图、弹窗或地物遮住关键目标/操作；图例可解释水上修正。

### 性能与资产

- 按 24×20、10v10、四区域及多人在途主地图测量；保存机器、浏览器、视窗和图集版本。
- 继续按需绘制，空闲时无持续重绘；动画结束及时释放临时对象。
- 地表/地物分层缓存，单位移动不重建整个背景；纹理由拥有者释放，场景卸载后异步加载不得写回旧实例。
- 素材 URL 尊重部署基础路径。断网/缺图时有相同语义的原生回退，不改变通行、命中或水战数值。
- 最终证据是实际可玩地图的截图与交互结果；概念图、独立 sprite 展板不算本轨道完成。

### 初始候选后续优先级与验收（历史，状态见第 11 节）

1. **P1 — 完成可交互镜头接线。** 由 App 集成负责人把相机状态、鼠标/触控平移、指针锚定缩放、Fit/Selected/All 定位与小地图导航接到本轨组件。验收：实际浏览器中缩放前后同一指针位置下逻辑格不跳，拖动不会触发格命令；键盘/触控替代操作可用；Wiki、语言和字号切换保留地图视口。
2. **P1 — 以真实地图数据核验地理叠层。** 由地理/集成负责人给出经过核对的河流、山系、路线、24 城锚点和四区战场 terrain 数据，并用程序数据绘制精确边界。验收：地图艺术只提供气氛；主河、山系、岸线、战场水格、可走性及城市/路线位置分别与数据一致；四区截图可逐项复核。
3. **P1 — 补齐战役地图部队可视层。** 为移动军队/运输队实现稳定的路线进度、行程/ETA、重叠聚合和展开视图输入，并遵守情报可见性。验收：地图日期/重绘不会推进时间或改动存档；同一路线多队伍可逐个查看来源、目标、剩余天数和状态，且不泄露不可见敌情。
4. **P1 — 补齐可访问性和设备验证。** 增加格子键盘导航与路线键盘激活；验证战场在 390、1366×768、1920×1080、中英、大字号、200% 浏览器缩放下可读且关键控制可操作。验收：不能只凭颜色区分的状态有形状/文字补充；焦点、提示和点击位置明确；无关键目标被小地图/弹窗遮挡。
5. **P1 — 做完运行表现验收。** 在实际低端设备、24×20、10v10 与四地域图上记录机器/浏览器/视口、FPS或帧时、内存和加载耗时；证明静止场景不持续重绘并在缺图时回退。该实机检查由用户完成并记录结果。
6. **P2 — 依据用户视觉意见修订并锁定美术。** 按第 06 轨待办对资产做有针对性的调整，更新素材和清单证据；用户完成实际游玩/视觉复核后再批准。验收：所有通过审核的资产在实际缩放下不会掩盖地形、单位、范围、标签或交互焦点，所有七个当前候选得到用户明确确认（可对一组实机截图共同审核）。

只有上述必需项验收、人工视觉确认和用户低端设备检查都留有可复现证据后，05 才能转为完成。
