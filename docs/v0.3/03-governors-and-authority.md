# V 轨：太守自治、征调和出征命令

负责人：治理/战略 AI 轨。状态：月界任免、辖城月度自治、D8 征调/出征方案、返程请求、月度事件，以及用户批准的旧版装备/赏赐/赈济规则已接入 v0.3。核心路径有自动测试，完整当前状态见[实施台账](implementation-status.md)。玩家已确认 D5–D8 与装备、奖励、赈济规则，见[共同合同](00-decisions-and-contracts.md)。本轨负责城市权限与决策；运输日期归 [L 轨](02-calendar-and-logistics.md)，临阵战斗归 [B 轨](04-battlefields-and-water-combat.md)。

## 当前实现更新（2026-10-21）

第 1–7 节定义目标合同；本节记录当前代码和自动测试。自动化测试不替代长战役体验或人工平衡评估。

### 已实现并有针对性测试

- **权限与自治城市工作**：玩家只能直接管理本势力君主本城；正式太守辖城与自治城不能通过普通城市命令直辖。月界规划器在各方非直辖城市执行，每城按驻城武将数（最多 3 点）消耗工作额度，按确定性优先级选择忠诚恢复、农商、治安、征募、训练、搜索、宴饮、买卖粮、编兵、赏赐、精良兵器或赈济。玩家与太守共用城市工作费用、效果、兵力和额度校验；计划保存资源/人员/RNG 快照，状态变化后拒绝过期计划。它会保护安全粮、已批准资源/兵力预留和至少 1,000 预备兵；有敌军威胁时暂停城市发展动作。证据：`tests/v03/governance/city-actions.test.ts`、`autonomy.test.ts` 及引擎月界/战斗回归。
- **月界任免与跨城调任**：本地任免在结算边界生效；外地候选人须以无兵调任行程抵达后再于月界就职。原太守在交接月界前仍保留原职；正式交接时才解除来源城任命并恢复地方自治。在途候选人被替换或目标城失守时，会撤销待办并请求沿安全路线返回；迟到会说明原因并顺延，捕获、死亡或失效候选人会清除待办且保留现有治理。失去返程城市时，行程会转向当前可达的友方避难城市。玩家已确认保留无兵调任规则（见[实现决定](00-decisions-and-contracts.md#10-后续确认的实现规则)）。`divided-realm-190` 与 `guandu-200` 均有“征募预备兵—归还候选人所部—调任—月界任职—存档往返”的引擎测试。证据：`tests/v03/governance/appointments.integration.test.ts`、`governance-scenario-chains.integration.test.ts`、`tests/v03/engine.integration.test.ts`。
- **征调/出征方案与返程**：订单评估使用真实路线、队伍、补给、守军余量、数量差额和期限；玩家可缩减、等待或取消，答复在战斗阶段原子拒绝，过期方案会重新评估。已派出的行程可提出安全返程请求并沿路线返还在途人员/货物；已进入战斗的队伍不能被即时召回。界面已显示路线、距离、预计日期、缺口及合法确认选项，并可输入需求数量/期限。证据：`tests/v03/governance/orders.test.ts`、`tests/v03/engine.integration.test.ts`、`src/v03/App.tsx` 订单面板。
- **月度战役事件、邀请与保存**：月界从存档 RNG 确定性结算联盟到期、反董联盟、旱灾及系统事件；董卓迁都实现为无攻城的洛阳撤离，迁移驻军和预备兵并扣减城池资产。反董事件已在真实引擎月界中触发，创建邀请/条约并通过存档校验。证据：`tests/v03/campaign/monthly-systems.test.ts`、`monthly-systems.integration.test.ts`。
- **订单与竞争者策略**：治理订单接入日历路线和真实行程，竞争者的出征规划在月结执行并扣除实际兵粮。证据：`tests/v03/governance/orders.test.ts`、`tests/v03/strategic-ai.test.ts`、`tests/v03/engine.rival-dispatch.test.ts`。

### 尚未满足的合同与限制

- **任命恢复与边界**：替换在途人选、目标城失守、候选人捕获/失效、迟到顺延和来源城任职交接已有处理与测试。死亡专门路径及极少见路线失效/避难组合仍缺独立回归；跨城调任候选必须先归还所部，待单独决定是否改变。
- **调任候选必须无兵**：v0.3 已确认要求调任候选人的部队先归还预备兵。两个场景的归还—调任—月界就职流程有测试；携部队调任不在本版本范围内。若未来调整，需先覆盖行军、指挥权和编组影响。
- **月界自治不是完整的按日承诺履行 AI**：规划器在月界花费工作点；已知威胁会暂停发展，但不会自动组织防御。战略对手按自己的订单规划出征，不能据此声称已实现完整多前线或防守协调。
- **出征协同及日期估算仍有限**：没有跨城统一到达窗口或多城会师；“最早可行日期”基于当前库存、静态产出和路线的估算，并未模拟多月收支及随机事件。多城会师与复杂未来现金流仍属后续范围。

## 1. 玩家能做什么

君主本城直辖；正式任命太守的城市自治。任命后不是只增加民心，而是由太守组织城市人员和日常事务。玩家对辖城保留资源征调和出征指令；保留势力级外交、太守任免，以及玩家军队的手动战斗。

| 行为                                       | 本城         | 太守辖城的玩家             | 太守                     |
| ------------------------------------------ | ------------ | -------------------------- | ------------------------ |
| 查看信息、收支、订单与报告                 | 可           | 可                         | 可                       |
| 农商、治安、搜索、征募、训练、宴饮、买卖粮 | 可直接命令   | 不可直接命令               | 按城市需要组织           |
| 逐将编兵、装备、奖励、赈济                 | 可直接命令   | 不可逐项操作               | 按预算和合法动作执行     |
| 金粮/兵力征调                              | 直接组织运输 | 下达目标数量与期限         | 筹备、提出方案、组织运输 |
| 向指定城市出征                             | 直接编制     | 下达目标、任务、规模与期限 | 选将、配兵、筹粮、出发   |
| 任免太守                                   | 势力级权限   | 势力级权限                 | 不可自授权               |
| 外交/同盟                                  | 势力级权限   | 势力级权限                 | 不可独立宣战或毁约       |
| 手动战斗                                   | 可           | 可                         | 委任时由 AI 操作         |

辖城内逐将调任和俘虏处置由太守处理；若以后要开放君主特赦/特殊调将，应单列权限。首版太守不自主处决俘虏，避免给自治增加未请求的永久损失。既有“劫掠/突袭”意图可沿用，但不自行扩大目标或更改外交。

## 2. V1：任免与边界生效

本计划把 D6 的“结算边界”具体化为**下一个月界**：任命/免职立即进入待办记录，次月首日统一生效。候选人必须为该势力有效武将，实际到任需要 L 的调任路线；月界前未到任则顺延并说明原因，不瞬移。

- 当月继续按旧治理模式工作；不能通过连续任免获得新一轮内政额度。
- 一个城市最多一个待生效人事决定；新决定明确替换旧决定，已有调任旅程另行取消/返回，不能凭空删除。
- 君主本城保持直辖。更换本城是治理变更，也在月界生效，旧本城进入已指定太守/临时自治，不能同时多出两个本城。
- 空缺、死亡、被俘或太守出征时，由代理/地方班底维持自治；不突然恢复玩家直接操作。正式继任仍走任免流程。
- 换太守不清空队伍、库存预留、工作记录、冷却或出征承诺；说明哪些未出发方案需要重评。
- 现有 `chooseGovernor` 的“自动选最高智力者”只可作为临时代理建议，不能悄悄覆盖正式任命。

在界面显示现任、代理、待任人选与预计生效日期。第一次任命提供简短权限说明，但不每回合重复确认。

## 3. V2：真正的权限边界

建立共享的 `getCapabilities` 查询和规则层校验。城市按钮、武将详情、快捷键、顾问建议和旧弹窗均读取同一结果。即使 UI 被绕过，直接构造 `action/assignTroops/transfer` 命令也不能微操自治城。

内部 AI 使用受控的“辖城代理执行上下文”，由引擎根据身份和当前任命授予。普通命令不能仅通过自报 `actor=governor` 越权。给内部动作和玩家动作共用费用、体力、兵力上限与合法性检查。

失败命令返回原状态；不得提前扣款、推进 RNG 或消费动作额度。语言改变不改变能力查询结果。

## 4. V3：征调令

请求内容：来源城、接收友城、金/粮/预备兵目标、希望期限。目标是运输到城市，不设即时全势力共享仓库。

状态：`requested → proposed/accepted → reserved → dispatched → delivered`；另有 `waiting/rejected/cancelled/returning/failed`。为每次执行分配稳定 ID，方案必须引用其评估时的库存和权限修订号；接受时再次验证。

太守给出四种答复：

1. 能全部执行：明确数量、出发日、预计到达日及守城余量；可按原要求直接承诺。
2. 只能部分执行：列出可交付数、缺口和影响，等待玩家选择缩减或继续等候。
3. 可以筹备：列出预计最早日期和条件；玩家可保留要求、修改期限或取消。
4. 当前无合法方案：解释道路中断、无护送者、缺粮/守军不足等具体原因；给出再次评估条件。

“最早日期”是基于可知产出、当前路线和已承诺任务的估计，不承诺随机事件一定发生。不知道时显示无法确定及缺失条件，不能假造一个准确日期。

承诺后资源进入预留；出发后由 L 唯一管理在途账本。玩家只看报告、接受新方案或取消，不通过运输弹窗挑走辖城任意武将。兵力征调的护送者与阵容由太守安排，必须清楚显示，但不开放逐将改动。

## 5. V4：出征令

输入目标、征服/突袭/劫掠意图、兵力区间与最晚出发日；输出将领、兵力、口粮、路线、预计抵达及守城风险。

- 首轮每城最多一份活跃出征指令，可修改尚未承诺部分；不把修改变成第二次资源预留。
- 玩家批准方案后，太守负责准备、部队组成和出发。若实际规模低于玩家要求，必须重新答复，不能悄悄少出兵。
- 不因暂时缺粮自动进攻另一个城市，不自行取消外交约束。
- 多城协同使用统一的目标到达窗口。等待军队需口粮，延期可解释；错过窗口重新协调，不能按旧“同月必到”执行。
- 太守本人可任带队将领；城内留代理。玩家仍能手动操作这支军队，开战时显示手动/委任选择。
- 已出发取消转成返程请求，战斗内遵循战斗撤退；不即时回城或退款。

## 6. V5：自治规划器

每月分配人员工作额度，按日检查到达、威胁和批准命令是否可开始；不能每天重新赋予每月工作次数。规划器可按稳定事件触发重评，不因打开面板多跑一次。

优先顺序建议：维持口粮/军饷 → 兑现批准承诺 → 防守已知威胁 → 恢复民心/忠诚 → 训练与农商发展。不得为履行征调把本城守军和生存粮全部清零。

“安全储备”采用公开配置：下次结算前口粮、已有承诺、受威胁城市留兵需求。太守智力/特性影响选择效率与优先级，首轮不增加政治属性、不用隐形随机浪费惩罚玩家。忠诚低的随机抗命另做内容设计，首轮答复先基于客观条件。

复用现有城市规则服务，禁止直接增加金币、跳过体力或强制解锁武将。战略对手使用同样自治和路线逻辑，战略 AI 负责目标，太守负责履行，避免两个 AI 抢用同一批人。

## 7. V6：报告与界面

独立组件建议：治理卡、征调表单、出征目标表单、待确认方案列表、承诺/运输明细、月报。总页面接线由 I 完成，R 提供地图选城与路线预览。

中英说明必须回答：谁负责、能送多少/出多少、何时出发与抵达、缺口多少、为什么延迟、玩家下一步有哪些合法选择。城市内政按钮可显示禁用原因，但不能留下功能可用的快捷入口。

报告从已发生事件生成，按命令 ID 关联，不重复打印每次预览。全部数据可在 Wiki 查看解释；Wiki 本身不执行命令。
