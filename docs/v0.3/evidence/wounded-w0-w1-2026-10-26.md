# 伤兵机制 W0 / W1 实施记录

日期：2026-10-26。分支：`hegemony_of_the_three_kindoms_v0.3`。起点：`3a53501`；本记录对应本地工作区改动，未创建提交、推送或 PR。

范围：[实施计划](../10-wounded-system-implementation-plan.md)的 W0 和 W1。这里只完成数据、查询、转移工具与存档基础；战斗减员尚不产生伤兵，自动治疗、整编倒计时、新撤退判俘和俘虏军队处置仍待 W2–W6 接通，不作为完整伤兵玩法交付。

## W0 基线与已确定契约

- 原有工作区含设计文档和城市美术文件；美术及其生成记录保留，未混入本功能修改。
- 初始 TypeScript 检查通过；兵池、兵力流转、战斗、战斗经验、存档五组测试基线为 107 项通过。
- 武将仍为单一兵种，新增 `wounded`、`reorganizationDays`。独立留城记录持有实际人员；城市预备兵与战场、行程汇总不是额外副本。
- 留城记录用独立 ID 区分；同一将军可多次留下不同经验或整编日数的人员。原将改投不改变留城人员所属势力。
- `personnelDay` 与交互推进用的 `DayResolution` 分离；新局建立日初资格，跨日后在处理新抵达人员之前建立下一日快照。后续 W4 执行恢复与整编，不在 W1 提前触发。
- 日资格和已供粮人数随现有拆分／归队工具转移，防止以新记录重新取得当日额度。日中恢复、供粮以及所有命令入口的完整接线仍属于 W3/W4。
- 路线明确使用移动方势力，允许失守城或看押城作为离开起点；实际 `planRoute` 和改道实现仍由 W3 修改。
- 存档公共版本仍为 3、`ruleset` 仍为 `hegemony-3`，新增必需的 `personnelSchema: 1`。不迁移此前结构。

### 执行环境说明

最初 Vitest 在沙箱临时目录发生 `EPERM rename`，尚未执行测试；将本进程 `TEMP` / `TMP` 指到已忽略的 `node_modules/.cache/wounded-temp` 后正常执行，没有改动项目测试配置。

首次并行全量运行的战术性能用例测得 p95 83.53 ms，未达到 50 ms；另有一个旧看押 fixture 失败，已修正为实际城市看押。随后全量以 `--maxWorkers=1` 重跑，426 项全部通过。没有降低性能阈值，也不以这一结果宣称实际低端设备验收通过。

浏览器测试在沙箱中无法连接本地开发服务器，改用获准的本地执行环境；不将连接失败算作浏览器功能已通过。
