## 已实现规则

- 空的本地在野池在共享资格检查中拒绝；城务搜索入口禁用并解释原因，不扣工作点、不抽随机数。正常搜索保留原抽选、成功率及忠诚规则，失败正常扣一点；成功不赠兵、经验或职务。未登场、已故、在职、被俘、行军、在战者不进入搜索池。
- 玩家只直接办理君主本城城务。NPC 首都另有内部执行入口，必须匹配当前势力、城市主人及首都；普通命令和伪造自动标志不能绕过权限。地方城沿用自治，围城或敌军威胁时暂停，工作人员不足时没有凭空的工作点。
- 每城每月最多三工作点，自动搜索、首次编兵分别最多一次，使用 `autoSearchesThisMonth`／`autoAssignmentsThisMonth` 和同一个工作月份保存。失败搜索也记录次数；读档、普通工作、归还后再编兵或迁都不清零。手动搜索可继续使用剩余工作点。
- 紧急粮草、治安、忠诚事项优先，再按武智合计降序和 ID 选合格零兵将。对象须同城本方、存活、无健康兵也无伤兵、整编结束且未被批准命令预留；不强制选择太守。
- 同兵种可支配兵员至少 100 人才首次编入，最多 500 人；99 人不会直接编入。库存不足可先正常征募目标兵种，能力取管理者，不把受兵者当成征兵执行者；扣真实费用、人口及工作点，编兵另扣一点，不能混用其他兵种库存。
- 执行前重新规划并核对归属、目标状态、库存及经验、命令预留、预算、工作点和月份，拒绝过期计划且无副作用。可选事项不可负担时继续检查其他合法事项，食品不足时不扩军。
- 月结完整回填 `troopSources` 与 `personnelDay`，修复旧代码只回填人物和城池而漏掉兵员来源、口粮记录的问题。编兵转移真实兵员及经验，不增加兵员总数；已付口粮随兵员转移，当日不重复计粮，次日恢复正常消耗。预备兵、伤兵、后方原部及俘虏仍按既有粮耗计算，骑兵权重为两份。

## 测试与实跑

新增 [44 项招募及编兵集成测试](../../../../tests/v03/governance/officer-recruitment.integration.test.ts)，覆盖首都／地方城、99／100／499／500／501 库存、异兵种、普通预备兵与原部经验、已批准命令、工作点与每月次数、手动重复搜索、失败扣点、伤兵和整编排除、过期计划、越权及存取。正常资源条件下，两种城市均通过真实月结完成搜索及两个正常月结内编兵；新部可进入既有战略 AI 出征。
