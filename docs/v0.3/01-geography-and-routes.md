## 3. 距离怎样得到：保证可以重算

### 3.1 直线距离是真实地理量，仍受锚点误差影响

表中“直线”实际为球面大圆最短距离。用上表纬经度、平均地球半径 `R = 6371.0088 km`，角度先转弧度：

`a = sin²((lat2-lat1)/2) + cos(lat1) × cos(lat2) × sin²((lon2-lon1)/2)`

`D = 2R × asin(min(1, sqrt(a)))`

输出按最近 5 公里四舍五入；内部计算使用未四舍五入的 `D`。**绝不把屏幕像素距离代替公里数**，也不把大圆距离直接当作可行军的道路长度。

### 3.2 本轮路线估算模型

没有逐段测长的边，先按下列公开模型推算。系数与地形占比是**可调设计估算**，不是史料给出的固定常数。路线绕行系数表示路径弯曲长度；速度按路面/地形计算，二者含义不同。

| 类别 | 道路公里 = D × 系数（低 / 名义 / 高） | 平地 / 丘陵 / 山道长度占比       | 使用场景                         |
| ---- | ------------------------------------- | -------------------------------- | -------------------------------- |
| P    | 1.15 / 1.25 / 1.35                    | 100% / 0% / 0%                   | 连续平原；仍须避水和走渡口       |
| H    | 1.25 / 1.40 / 1.55                    | 50% / 50% / 0%                   | 盆地边缘、丘陵、谷地连接         |
| M    | 1.50 / 1.70 / 1.90                    | 30% / 20% / 50%                  | 穿越山系、上游峡谷岸路           |
| R    | 1.30 / 1.50 / 1.70                    | 60% / 40% / 0%                   | 大河走廊**陆路**，不等于航行水路 |
| B    | 专项：400 / 425 / 450 km              | 固定 235 km 山道，余下为接近道路 | 本稿仅汉中—长安褒斜路线          |

路线低/名义/高公里值分别取最近 5 公里。其它边的地形占比只用于暂时估算，不足以直接绘制某个山口的位置。G1 取得可靠走廊后，应录入真实控制点、分段长度和来源，以该路段数据替代类别占比；不再叠加一次 P/H/M/R “地形耗时”。

### 3.3 历史依据和速度的可信边界

《孙子·军争》把弃辎重、强行争利与到达队伍损失联系起来，支持“轻装急行与整支带补给军队不能按同一速度”的原则；它不是一个可以直接套用的汉末军队公里/日统计表。[原典](https://zh.wikisource.org/wiki/孫子)

汉末的具体案例更能说明“队伍组成与任务”为什么必须进入公式：《三国志·先主传》记载 208 年刘备南撤时，同行人口与辎重很多，至当阳一段“日行十餘里”；同篇记曹操抛下辎重，以精骑追击，“一日一夜行三百餘里”。前者是携民众的撤退，后者是短时急追，都不能当作普通军队连续行军的通用速度。原文同时区分陆路队伍与关羽的船队，支持水陆路线分开建模。[《三国志》卷三十二原典](https://zh.wikisource.org/wiki/三國志/卷32)

本次没有找到足以证明“汉末每支军队正常每天统一走 X 公里”的可靠量化材料，也不把现代 1 里 = 500 米无条件套到汉代。以下属于结合这些历史行军差异、步行、辎重及山道约束的工程初值；具体公里数与倍率不是从上述两例机械换算而来，必须经长战役测试检验玩法节奏。

| 地形路段          | 正常混合军队名义速度 | 研究不确定性范围 | 解释                                               |
| ----------------- | -------------------: | ---------------: | -------------------------------------------------- |

以上按**战略历日平均**建模。正常短休整已在平均速度中，不能另外每三天强加休息日而不重新校准；封路、等待征粮、待渡与战斗暂停属于独立事件，不含在表内。

## 5. 汉中—长安专项：约一个月有理由，不能写死

[汉中市地理介绍](https://www.hanzhong.gov.cn/hzszf/mlhz/hzgk/202409/96f3304196fe4de4a13c848c03956a10.shtml)支持汉中在秦岭以南、汉江上游盆地的位置。两城大圆距离约 **225 km**，但行军要走穿山道路。

[汉台区政府《褒斜栈道》](https://www.htq.gov.cn/hzshtqzf/zjht/lswh/202104/ad1c853e723f40e68b72aa961214665e.shtml)给出褒谷口至斜峪关的谷道路程约 **235 km** 及沿途节点；[宝鸡蔡家坡管委会介绍](https://cjp.baoji.gov.cn/col3866/col3880/200810/t20081031_710038.html)说明褒谷口在汉中北约 25 km。**235 km 不是汉中城至长安城全程。**

本轮候选拆法：

| 路段                 |            本轮公里数 | 证据性质                                                   |
| -------------------- | --------------------: | ---------------------------------------------------------- |
| 汉中/南郑区域—褒谷口 |                 约 25 | 上述地方资料给出的区域距离，具体城门到谷口另核             |
| 褒谷口—斜峪关        |                约 235 | 官方介绍的历史谷道路程；仍是现代资料概述，不是汉末测绘清册 |
| 斜峪关—汉长安城      |  约 140–190，名义 165 | 本轮沿关中盆地衔接的人工估算；必须补控制点测长             |
| 全程                 | **400–450，名义 425** | 前述分量相加，不另乘山地绕行系数                           |

为给出透明的首轮估算，先将 235 km 计作山道，其余 165–215 km 计作接近道路：

- 名义：`235 / 10 + 190 / 20 = 33 日`。
- 短/快端：`ceil(235 / 15 + 165 / 25) = 23 日`。
- 长/慢端：`ceil(235 / 8 + 215 / 15) = 44 日`。
- 若后续认为接近道路部分包含明显丘陵，应把对应公里拆到丘陵段，重新计算；不能只把结论调回“至少 30 天”。
- 轻骑可以在接近道路更快，但山道瓶颈不能得到与平原相同的骑兵加成。名义轻骑结果约 `ceil(235 / 10 + 190 / 30) = 30 日`，这是这条具体候选路线的计算结果，不是强制下限。
- 陈仓道、傥骆道、子午道是候选替代走廊，不能未研究便给它们同一长度、允许通行或固定更快；v0.3 可先配置一条有说明的默认路线。

## 6. 单位/运输修正：先算道路，再算同行者

以下倍数表示**速度倍率**，不是天数倍率；1.5 倍速度对应相应路段耗时除以 1.5。它们是待战役验证的游戏参数，不是史料给出的兵种速度定律。

| 同行类别             |      平地 |      丘陵 |      山道 | 首轮规则                                                          |
| -------------------- | --------: | --------: | --------: | ----------------------------------------------------------------- |
| 步兵、弓兵           |      1.00 |      1.00 |      1.00 | 使用基础速度                                                      |
| 纯骑兵轻装纵队       |      1.50 |      1.20 |      1.00 | 只有没有慢速同行人员/运输车队才适用                               |
| 重装/大量辎重队      |      0.75 |      0.80 |      0.80 | 是否采用车/驮运由路段可通行条件决定；不能把车队直接开上不通车栈道 |
| 单名武将轻装调动     |      1.50 |      1.20 |      1.00 | 只是行程配置档，不因为“只有一个人”变成瞬移                        |
| 精锐、近卫等现有类型 |      1.00 |      1.00 |      1.00 | 类型名本身不授予速度奖励；由真实运输/装备属性映射                 |
| 现有 `naval` 类型    | 陆上 1.00 | 陆上 1.00 | 陆上 1.00 | 不把旧水军名称当作战略航运资格或战术入水门槛                      |

**混编规则：**每个路段按同行者中最低的有效速度推进；用加权平均会让少量骑兵“拖快”辎重队。调遣单骑、军队与运输队应是不同实体，但共用同一路线服务。不能在行军中拆出一匹马改变整队已消耗路程，或通过反复合并刷新出发日。

**与 D10 的关系：**战术地图上所有作战单位可以入水并受攻击、防御惩罚；这不等于整支战略车队自动能渡长江。战略过河由道路的渡口/桥梁通行段表达，没有水军技能门槛；如首轮加入城际航运，必须建立独立水路段、方向性与装卸时间，不能拿本表 R 类陆路里程直接称为航道里程。D10 的战术水战不等待完整航运经济系统。

正常行军先落地。急行军、四季随机天气、运输袭扰和复杂道路容量不应偷偷加入第一版公式；若实现环境已有此类修正，必须显示其理由且单独测试。原有“10/20/30 个战斗日军粮”不能直接当作 33 日道路行程的全部补给。

## 7. 给日历、行军、地图和太守代理的接口合同

### 7.1 G1 输出的静态数据

| 字段                                                | 要求                                                                                         |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `cityId, historicalSeatName, scenarioId/validYears` | ID 稳定；年代名称/位置覆写明确                                                               |
| `lat, lon, confidence, sourceRefs`                  | 地理锚点与证据；图标偏移不改此值                                                             |
| `routeId, fromCityId, toCityId`                     | 一条无向实体，两种行进方向；方向规则独立                                                     |
| `straightLineKm`                                    | 只用于审计与地图说明，不直接决定 ETA                                                         |
| `routeKmLow, routeKmNominal, routeKmHigh`           | 本稿初值；应有 `estimateMethod` 与修订说明                                                   |
| `segments[]`                                        | 每段 `lengthKm, terrain, travelMode, passability, controlPointIds`；长度之和等于名义路线公里 |
| `fixedDelayDaysByDirection`                         | 明确的待渡/装卸等静态耗时；未知先 0 并标待核，不能隐藏进骑兵倍率                             |

### 7.2 行军/日历代理输入输出

估算请求输入：`routeId`、方向、出发绝对日、同行单位/运输档案、当前剩余路段及路程、可用通行条件。由 G1 的速度表和路线段产生：

- 每段名义日工作量 `lengthKm / effectiveKmPerDay`，以及明确的固定等待。
- 名义总行程 `ceil(sum(segmentWorkDays) + fixedDelayDays)`；**只在行程末端取整一次**，不要每段向上取整制造额外天数。
- `arrivalDay`、`remainingDays`、`distanceRemainingKm`、中英双语 `reasonBreakdown`。
- 研究范围仅用于设计/高级说明；向玩家的“预计到达日”使用确定性配置。日历推进不会每天重新随机抽取速度。

日历代理拥有“出发当日是否消耗第一天、同日到达/战斗事件排序”的统一规定。G1 不另造日历。粮草代理收到预计历日和队伍规模，再叠加战斗储备；太守代理据此给“最早筹备完成日 + 行程 = 最早到达日”，并列缺口。地图代理读取同一 `routeId/segments`，不得维护第二份距离。

### 7.3 地图投影和图像生成边界

1. 用地理点生成保持方位与相对距离关系的投影；小范围标注可用等距圆柱近似，正式全国视图采用明确记录参数的投影。无论选何投影，ETA 仍用路线公里。
2. 可将标签/城市图标偏移以免重叠，但锚点与引线必须保留；相邻城市更大图标不能把区域硬挤回旧示意布局。
3. 将秦岭、太行、汉江、淮河、长江等地理控制线交付地图/美术代理。水墨背景跟随控制线，不能让 imagegen 自行安排山河位置。
4. 在江夏、北海、梓潼等 C 级位置冻结前，图像代理只做纸张、笔触、地表与城市符号素材/风格样张；无需等待地理研究才能并行工作，但避免提前绘制不可拆分的最终全国底图。
5. 路线提示显示“道路约 N 公里；普通军队约 D 日；山道 X 公里”等；研究不确定性可以在 Wiki 展开说明，不占据普通下令流程。
