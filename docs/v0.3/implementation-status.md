## Confirmed defects

All eight defects documented in the initial audit now have regression coverage and fixes in the working candidate:

| Finding                                           | Fixed behavior / regression coverage                                                                                                      |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| F01 fixed-point travel ration error               | Daily journey consumption uses a stable remainder ledger; tests cover 101 troops over ten days and food shortfall accounting.             |
| F02 raid cargo credited before/again at arrival   | Loot remains in the travel cargo ledger and credits once on delivery.                                                                     |
| F03 full destination store discarded cargo        | Undelivered cargo remains attached to its delivery/return path instead of disappearing at the capacity clamp.                             |
| F04 advancing over month/event boundary           | Day advancement stops at due event/month boundaries and resumes from the saved day cursor.                                                |
| F05 same-day return travel                        | A battle-created return journey begins moving on the next strategic day.                                                                  |
| F06 duplicate militia/officer roster identities   | Battle rosters use unique membership and count garrison militia once.                                                                     |
| F07 issuing player commands in rival-only battles | Command boundary verifies actual player participation before accepting a manual order.                                                    |
| F08 invalid cross-entity save references          | Save parsing rejects invalid journey/officer/order associations and duplicate active membership while preserving the existing valid save. |

See `tests/v03/engine.integration.test.ts`, `engine.rival-dispatch.test.ts`, `battle.test.ts`, `platform/storage.test.ts` and the focused governance tests for the regression coverage. The initial reproduction output is historical evidence, not a current-failure report.

## Decisions and external gates

- D1–D11 remain the agreed product contract. D11 uses `survivor-count`; the defender wins ties. Legacy battle tactics were accepted for porting. The user also confirmed that cross-city governor transfers keep the troop-free rule.
- The user accepted legacy governor reward, fine-arms and relief actions within v0.3's current monthly work-point and resource budget.
- The user chose to keep art draft for revisions and will complete four play sessions plus a real low-end-machine check. These gates remain open.
- Push, pull request and remote CI were explicitly deferred. A local commit on `v0.3` is authorized; remote operations are not part of this completion pass.
