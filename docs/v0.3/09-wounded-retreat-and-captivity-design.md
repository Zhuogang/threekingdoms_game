# 伤兵 撤退 被俘与恢复设计草案

创建日期：2026-10-25。复核日期：2026-10-26，已补充玩家体验、规则一致性与实施可行性复核。现行规则核对基准：`3a53501`，包含此前的士兵经验与分兵种预备兵提交。

**状态：W0–W6 已实现，W7 自动验证和三组机器短回放通过；长期人工平衡试玩待执行。** 第一节保留 `3a53501` 的实现前基线，便于理解改动，并非更新后的玩法。第二节起为本次规则；具体完成范围见[实施计划](10-wounded-system-implementation-plan.md)与[验证记录](evidence/wounded-system-2026-10-26/README.md)。最新玩家操作见[中英指南](player-guide.md)。

目标是让老兵和精锐在战败后仍有保存机会，同时保留战败、断粮和被俘的代价。第一版沿用武将所部、城市兵池、每日时间和现有俘虏操作，不引入轻重伤、军医、医院建筑、独立军团或士兵忠诚系统。

## 一 实现前基线怎么玩（3a53501）

### 一个将军带多少兵

| 问题                         | 当前实现                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 单将带兵上限                 | 固定为 10000 人，编兵输入范围是 0 至 10000；不随武力、武将等级或士兵等级提高。                                     |
| 一名武将带几种兵             | 只能带一个基础兵种：步兵、弓兵或骑兵；现有实现没有单将多兵种，补兵只能来自城市同兵种预备兵池。                     |
| 征兵时是否确定兵种           | 是。征兵时就选择步兵、弓兵或骑兵，新兵进入对应兵种的预备兵池；分给武将时不再选择或转换兵种。                       |
| 征兵会直接加到将军身上吗     | 不会。征兵先进入城市对应兵种的预备兵池，再用“调整兵力”分给武将。征兵执行者的个人兵种不改变本次所选招募兵种。       |
| 调整兵力的数字是什么         | 调整后的最终人数。例如从 800 改成 1000，会补入 200 人；改成 0 则归还全部所部。                                     |
| 出征能只带一半吗             | 出征界面勾选武将，带走所选武将的整支所部。要改变人数，应先在城中调整。自治城市还会经过出征方案、留守和资源检查。   |
| 三名武将各带 5000 人         | 出征总人数为 15000，不受“单将一万人”限制。                                                                         |
| 战场一个棋子等于一个将军吗   | 不总是。每方最多 10 个编队；超过编队容量时，同兵种所部会合并显示。一个编队可能包含多名武将，战后再分回各人的所部。 |
| 城里没有分给将军的守军怎么办 | 城市还可能有无主将守军，以民兵编队参战。预备兵与这类守军是不同账目。                                               |

武将自己的经验、等级和士兵经验、等级彼此独立。士兵等级为 `1 + floor(经验 / 100)`，最高 20 级；达到 11 级后，步兵显示为重步兵、弓兵显示为强弓兵、骑兵显示为精锐骑兵。它们仍属于原来的三种基础兵种，不是需要另建兵池的新兵种。

目前补入新兵会按人数稀释平均士兵经验；普通分兵保留平均经验。现有损失只会减少人数，可战人数归零后该所部的士兵经验会被清空，没有伤兵账目。

### 一场战斗如何进行

- 战场是 48×32 格，每方最多 10 个编队。玩家可移动、攻击、待命或使用计策；通常每个战斗日一次移动、一次行动，受状态限制。
- 步兵基础移动预算 3、普通射程 1；骑兵为 5、1；弓兵为 3、3。地形、占位和敌军控制区会影响实际可达位置。
- 普攻可能受到射程内敌军反击。所有兵种都能进入可通行水格；水上攻击乘 0.75、受到兵力伤害乘 1.25，移动也更慢。
- 士气初始为 80。低于 40 为动摇，低于 20 为溃败；溃败单位仍可能有兵，只能移动或待命，不能攻击或用计策。
- 普通战斗最多 30 日，突袭最多 10 日。到期按剩余兵力比较，多者胜、相同则守方胜；目前该人数包含尚有兵力的低士气单位。
- 一方兵力全部归零、所有尚有兵力的编队都士气溃败、敌营被有效占领，或者一方主动撤退，均可能提前结束战斗。
- 敌营是野战目标。当前没有城墙攻防、城门突破或第二阶段攻城；征服战的野战结果直接进入城市归属结算。
- 所有需要玩家处理的战场都结束本日操作后，世界时间才统一推进一天；纯 NPC 战斗自动处理。

### 主动撤退现在究竟是什么

当前入口在战场侧栏的“更多操作 → 撤离战场”。需要有选中的存活编队，且本日尚未提交；点击后会确认，取消或 Escape 不改变战况。

**确认后是己方整场认输，立即结束本场战斗。选中的棋子只是命令入口，不代表只撤走该棋子或该将军。** 不需要走到地图边缘，也没有逐队离场、追击阶段或额外撤退伤亡。

当前实际后果存在攻守差异。下表是现行代码行为，其中“守方失城全俘”是待修正问题，不是本草案采用的设计；新版统一按将判定被俘，见第四节。

| 情况                                       | 当前结算                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------------- |
| 攻方撤退或落败，尚有兵力                   | 剩余有兵的所部开始真实返程；归零所部的武将可能被俘。                       |
| 攻方剩余兵力全部归零                       | 参战武将全部被俘，没有纯伤兵返程。                                         |
| 守方在征服或劫掠占领战中落败，包括主动撤退 | 城池易主，仍在本场战斗中的守方武将全部被俘；没有守方向其他友城撤退的流程。 |
| 突袭攻方获胜                               | 不占领城市；攻方携战利品返程，守方仍留原城。                               |

因此，“我点击了撤退”目前只保证结束战斗，不保证所有武将安全撤走。拟议机制取消守方失城全俘，也不将主动撤退设成必定逃脱；必须同时调整战后去向，不能只给兵力新增一个伤兵数字。

### 现在的粮食和俘虏规则

现行每人每日基础粮耗为驻城 0.004、行军 0.008、战斗 0.04；骑兵按两倍计算。城市按实际驻留兵日累计、到月界结账；行军和战斗使用随军口粮。返程需要真实时间，不是战报确认后立即回城。

俘虏已有释放、招降、交换、处决四种操作。招降概率按忠诚计算，范围为 5% 至 90%；交换现为 75% 成功率。每名俘虏每月最多接受一次处置尝试。当前释放、交换直接修改驻地，没有独立的归还行程；俘虏所部也没有完整的粮耗、伤兵和军队移交规则。

君主被俘后，由自由武将继位；没有自由武将则势力覆灭。新机制不因还有伤兵而自动豁免这一规则。

伤兵比例 60%、溃退时保留三分之二伤兵、接战后有序撤退被俘率 5%、被迫溃退被俘率 25%、每日恢复比例 10%、招降整编期 10 日都是本次已接入的第一版默认调参值，尚未经过长期玩家试玩验证。主动撤退风险低于被迫溃退，无退路时仍按投降处理。溃退未带走的伤兵计失散和永久损失，不另建无主战俘池。下文明确未接战退却、后方休养和整编的适用边界。

单将单兵种是本版明确约束，不新增混编或转兵种入口。出征军队可以由分别带步兵、弓兵、骑兵的多名武将组成；战场临时合并也只合并同兵种所部。精锐骑兵等仍是原基础兵种的等级表现，不改变该约束。

## 三 伤兵如何产生和保留

### 可战兵 伤兵与永久损失

可战兵参加战斗，伤兵保留原兵种和士兵经验但不能战斗。伤兵是暂时不能作战人员的统称，包括仍可行军的轻伤者与体力耗尽者，不代表全部无法移动的重伤员；因此允许纯伤兵返程，而不另建担架或运输系统。战斗中的减员按固定比例转成伤兵和永久损失，比例对三个兵种、普攻、反击及伤害计策一致，暂不增加火攻更致命等差异。

例如一次有效伤害让可战兵减少 500 人，则其中 300 人转为伤兵，200 人永久损失。一次攻击只能减少目标现有的可战兵，不能重复伤害已经转入伤兵的人。

小额伤害的比例余数需要累计，避免把同样的伤害拆成多次攻击就改变最终伤兵数。非战斗减员如逃亡、断粮损耗，不会再次生成伤兵。

可战兵归零后，单位从可操作战场和占位中移除，不能再行动、反击、占营或成为攻击目标。伤兵作为该部队的随军人员留在记录中，不生成可移动的伤兵棋子；本场战斗不会恢复可战人数。

术语统一为：**“击溃”指可战兵归零，“士气溃败”指士气低于 20，“全灭”只在可战兵与伤兵都没有时使用。** 一个士气溃败但还有 1000 可战兵的部队，不会凭空多出 1000 伤兵。

### 士兵经验

可战兵与伤兵共用所部的平均士兵经验，继续采用“均匀损失、均匀分兵”的简化。只有两者合计为零，才清空士兵经验；伤兵恢复、逃脱、被俘、释放和招降本身不加减经验。

实际参战人员的生还者，包括本场新增伤兵和被俘者，按现有参战、伤害、胜利公式获得一次战斗经验。战前已受伤、未上阵的人员不领取本场奖励，即使同一武将还有其他人员参战也不例外。伤兵反复恢复不获经验。

需要把参战生还者与未参战伤兵汇总为同一个平均经验时，先计算本场奖励对应的人员占比，再加权。例如经验池中本场有 100 名参战生还者、另有 4900 名未参战伤兵，本场每名参战者应获 40 经验，则这个 5000 人池的平均经验只增加 `40 × 100 / 5000 = 0.8`。不能让少量可战兵代替大量未参战伤兵刷经验。

临时合并的战场编队，仍按战前成员人数比例分配减员与新增伤兵，确定整数余数归属；各原始所部保留自己的经验，再分别应用本场奖励。不能把一个棋子的平均经验覆盖到所有成员身上，也不能把所有伤兵分给其中一名武将。

## 四 撤退与战后去向

### 可用退路的定义

退路是大地图上到己方城市的可用战略路线，不根据战场棋子是否站在边缘、是否被邻格包围逐一判断。第一版不新增突围小游戏或追击回合。

先从可达友城中优先选择未交战城市，再应用目的地顺序：攻方优先原出发城，其次预计行军日最少的友城；守方选择失守城市之外预计行军日最少的友城。如果全部可达友城都在交战，在这些城市中应用相同顺序并城外等待。预计日数相同则按城市稳定 ID 排序，保证读档和 NPC 结算一致。

不穿过当前规则禁止通行的敌城；路线搜索复用现有地理图，但必须以撤退部队所属势力判断通行，不能以战后出发城的新城主判断。失守城市可以作为撤离起点，之后仍不能借此穿越其他敌城。优先选择未交战友城；只有可达友城正在交战时，可以退往该城外等待，抵达前或等待中不能恢复伤兵，也不会作为增援直接加入那场战斗。“暂时不能入城”不等于无路可退。

仅在不存在任何可达己方城市时，才视为无可用退路。有路只表示逃脱者有可去之处，不代表免除接战后的被俘判定；没有退路的整军撤退须明确显示为投降，不能在点击后才告知玩家全部被俘。

### 各类结束方式

| 战场结果                   | 战败方处理                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| 主动撤退 `retreat`         | 有退路时，未接战则全员退走，已接战则每将被俘率 5%；逃脱者保留全部剩余随军人员。无退路则投降。 |
| 超时失利 `dayLimit`        | 有退路时按有序撤退处理，已接战每将被俘率 5%；若始终未接战，则不凭空抽取俘虏。无退路则投降。   |
| 可战兵全归零 `elimination` | 改称全军被击溃，按被迫溃退处理；伤兵不能阻止战斗结束。                                        |
| 全军士气溃败 `rout`        | 按被迫溃退处理，仍有的可战兵保持可战状态，不自动转伤兵。                                      |
| 无胜方的平局               | 双方不互俘；守方留城，攻方有退路则有序返回。无路可归者按既有行程等待或改道流程处理。          |

主动撤退确认框必须预告：整场认输、城市是否失守、撤退目的地、可战与伤兵人数、每将被俘率，以及无退路会导致投降。确认前不抽签也不改变状态；取消和 Escape 仍无后果。已有战果不能通过撤退按钮撤销。

未接战指本场尚无任何一方发起普通攻击或敌对计策；普通攻击的接战标记由玩家、AI 和反击共用结算记录，不以玩家是否手动攻击作为条件。不能通过补满兵力或移回原位重新变成未接战。发现兵力判断有误就立即退却，代价是本次出征的行程与口粮，以及守方可能放弃城市，不应再凭空损失武将。已满足全军击溃或士气溃败的结束条件时，即使尚未提交结算，也不能用撤退按钮改成较低风险结果。

第一版不设单将主动离场。按钮可以保留在侧栏，但应更名为“整军撤退”，摆脱对选中存活单位的依赖，避免误解成撤走一个将军。

### 攻守双方统一按将判俘

先检查退路，再按武将逐人结算。没有退路时全部被俘；有退路时，未接战退却不判俘，已接战有序撤退每将被俘率为 5%，被迫溃退为 25%。攻方与守方使用同一张概率表，不因守方失城而额外判定全俘，也不叠加武力、骑兵速度、忠诚或地图位置修正。

每将概率需要让玩家看懂整军风险：10 名武将各有 10% 被俘率时，至少一人被俘的概率约 65%；降为每将 5% 后仍约 40%，而不是整军只有 5% 风险。确认框同时显示本场将数与“至少一将被俘”的概率。5% 是这次复核后的暂定值，需要通过实际战役检查是否仍偏高。

- 有序撤退中逃脱者带走全部剩余可战兵与伤兵，不额外扣撤退损失。
- 被迫溃退中逃脱者带走全部剩余可战兵，以及 `floor(伤兵 × 2 / 3)` 名伤兵；未带走者记为失散，计入永久损失。
- 被俘者及其全部剩余可战兵、伤兵一起落入胜方手中，不再额外扣一次三分之一伤兵。
- 可战兵为零但有伤兵的将军同样可以逃脱，并生成纯伤兵返程。
- 两类士兵都没有的将军仍然可以按相同规则独自逃脱或被俘，不因此自动战死。
- 每名武将只抽一次，结果随结算保存；刷新报告、重复确认和读档续算不得重新抽签。

暂不增加战斗中抓将和武将随机战死。临时编队包含多名武将时，各人独立判定；被俘一人不牵连编队里的其他人，更不牵连该势力的其他军队。

### 攻守双方与城市归属

征服或劫掠占领战中，攻方获胜仍接收城市，但守方先按上述概率撤走或被俘，取消“落城后所有参战守将自动被俘”的旧逻辑。主动撤退失城按有序撤退概率处理，不能直接全俘。纯伤兵所部和未生成棋子的驻城武将，也纳入同一结束原因的去向判定，不能留成敌城里的自由部队。

已经留在其他友城的伤兵不参加本场判俘：将军在外地被俘，不会让后方伤兵一起传送进敌营。成建制被俘只覆盖随该将参与本场的人员。仍在本次失守城市里的战前伤兵，无论原先是否挂在武将名下，均按留城人员规则解除编制；不能因为将军没有上阵而避开这项损失。

突袭获胜仍只抢掠、不占城：守方回到原城，保留所部伤兵；本版不把突袭胜利扩展为俘获守方整军。突袭攻方失败时，仍按其实际失败原因处理撤退与被俘。

胜方可战兵归零但有伤兵时，也保留人员并安排驻城或返程。城市只有伤兵、未整编人员或尚未配给守军的预备兵时，不算有可用守军。必须移除现行“无编队时至少生成 500 民兵”的保底；有实际无主将守军才生成民兵。确实无可战守军时直接进入同一套占领或突袭结算，不开启空战场、不凭空造兵，也不发未发生的战斗经验。

失城时，仍在城内的原势力自由武将也必须有去向，包括零兵武将、只有旧伤兵的武将和所部尚在整编的武将：按本场同一结束原因、退路和逐将概率逃脱或被俘，不能原地滞留，也不在已经结算过的参战者之外再抽一次。他们未上阵的人员属于留城库存，按失城规则解除编制；这里不增加秘密携带后方兵源撤离的通道。未开战直接失城按未接战撤离处理：有路则撤走武将，无路则被俘。中立在野武将不因城市易主自动成为战俘。

撤退和返程都有真实行程，最早从战后下一战略日移动；伤兵不瞬间传送回城。第一版不新增伤兵运输速度惩罚，但纯伤兵队伍按普通队伍速度行军，不享受纯骑兵轻装加速。返程目标途中易手时，复用等待、改道和重新选友城流程，不重复结算本场逃脱。

## 五 被俘部队与处置

### 人员归属与看押

武将被俘后，所部仍保留原势力、兵种和经验，处于看押状态；胜方不能把他们直接算进守军、出征人数、可用预备兵或留守要求。俘虏即使伤势恢复，也仍是俘虏。

能留在新占城市时，就在该城看押；胜方要返程时，俘虏随胜方行程押送，到达后入城看押。不能因为战场位于敌方城市，就把俘虏记录为由该敌城看押。押送人员与己方作战人员分账，但都计粮食需求。四种处置仅在入城看押后开放；押送中显示目的地与预计抵达时间，不提供在途招降、交换或就地转人口的额外流程。

看押城市被攻下时，原属攻城方的俘虏获救，转为自由所部；其他俘虏转由新城主看押。保留当时可战、伤兵与经验，不免费复活、补满或升级。

### 沿用四种处置

| 操作     | 对武将与所部的效果                                                                             |
| -------- | ---------------------------------------------------------------------------------------------- |
| 招降成功 | 武将及其现存所部一并加入看押方，保留人数、兵种和经验；所部开始 10 个有效日整编，伤兵继续恢复。 |
| 招降失败 | 继续看押，人员和兵种经验不变，本月不能再次招降或交换，但仍可释放。                             |
| 释放     | 武将带现存所部返回原势力的可达友城，途中暂停治疗。                                             |
| 交换成功 | 双方各自归还对应武将及其现存所部，按真实行程返回。                                             |
| 处决武将 | 武将死亡；所部解除军事编制，转为看押地人口，兵种经验消失，不自动加入胜方军队。                 |

沿用现有招降概率与交换成功率；每月次数限制只约束招降和交换这类概率尝试，释放与处决不受失败尝试的月锁限制。交换消耗双方所选武将本月的概率尝试机会，无论成功与否；预览和非法命令不消耗机会。不再引入士兵单独招降或军队忠诚。招降一名将军可获得其整支现存老部队，作为胜利收益保留；但这批人员不能招降当天就掉头攻打原势力。

所部在己方城市完成 10 个有效日整编后才可作战、计入可用守军或接受征调；整编期照常吃粮，有伤者可以同时恢复。这里只增加一个剩余整编日数，不另建第三种士兵数量，也不再区分训练、换装、忠诚等阶段。界面将其显示为整编中暂不可用，军力估算统一按可用人数计算。归还预备兵、换将、拆分或跨城移动都保留未完成的整编限制，不能通过配兵绕过；在途和无粮日暂停。未整编人员单独保留来源记录，不因同兵种汇总而冻结其他正常部队。武将本人可以承担合法内政。原势力通过释放、交换或攻城救回所部，不再额外罚一次招降整编期；尚未结束的既有整编限制也不会因释放而被抹掉。

以当前粮耗计算，3000 骑兵每月驻城吃粮 720；单靠这份粮耗，不能断言它足以抵消免费获得精锐的收益。10 日整编主要防止战后立即借敌兵连续扩张，长期招降收益仍需试玩观察，不提前宣称已经解决胜方滚雪球。

释放和交换时，确认框显示归还人数、兵种、伤兵和目标城市；有可达归属城市时，部队正常返还。归还路线按获释方势力计算，看押城市只作为允许离开的起点；不使用看押方的城市网络伪造可达性。释放不能因为无路返乡就被禁用：若原势力已覆灭或无可达归属城市，界面明确改为“释放武将并遣散所部”，武将成为当地自由身，所部就地解除编制转入人口，不生成无目的地军队，也不要求玩家处决武将才能停止养俘虏。交换仍要求双方都有可执行的归还行程。

返乡口粮由看押城现有库存拨付，上限为本次路线预计粮耗；确认框显示实际拨付量，不凭空补粮。当天仍先计看押责任，返乡行程最早下一日移动并供粮；粮食不足不会封死释放出口，但途中按既有行军缺粮规则记录短缺。

现有君主继位、势力覆灭规则继续生效。被俘将军尚有精锐伤兵，不代表其原势力仍有自由武将。

整编计日只在己方城市进行。被看押时允许按统一规则治疗伤兵，但不推进原有所部的整编；获释返乡和历史事件转移驻地均保留剩余整编限制，抵达本身不会使这些健全兵变成守军或民兵。

### 无主将人员

无主将民兵的伤兵在城市仍归原势力时，进入该城的步兵伤兵池。城市被占领后，留城的无主将守军、城市伤兵池和预备兵统一解除编制并计入当地人口，不能成为攻方可立即使用的兵源；相应士兵经验清除。

这是第一版避免增加“无主战俘营”的明确简化。它不影响跟随被俘武将的成建制军队；处置后人数只进入人口一次，不同时保留在伤兵或预备兵中，并遵守现有资源上限。人口超上限的部分明确记为人口外流；军粮超过接收城市上限的部分明确记为溢出损失，不隐藏消失，也不为处理溢出另建仓储系统。

## 六 恢复与补兵

### 每日自动恢复

每天恢复现有伤兵的 10%，新增伤兵只加入现存人数，不重置旧伤兵的治疗。第一版取消逐所部的 30 日恢复倒计时，不维护医疗批次或医院床位；只保留人员来源、兵种和经验所需的部队记录。

为避免拆分小队获得整数收益，每个城市先按步兵、弓兵、骑兵汇总全部符合休养条件的伤兵，包括所部、城市伤兵池和被关押伤兵；该兵种当天恢复 `ceil(伤兵合计 × 10%)` 人，不超过现存人数。再按各所部和兵池日初伤兵数比例分配恢复人数，整数余数稳定分配。分配后仍保留各自归属和经验，不把俘虏治疗成己方兵，也不把不同兵种混在一起。

例如 3000 名伤兵，在没有新增伤亡、断粮或转移时，首日恢复 300 人，约第 7 个有效日恢复一半，第 22 个有效日累计恢复九成，全部恢复需约 60 个有效日。尾部伤兵恢复较慢，但玩家不需要等全部恢复才能再出征；出征时余下伤兵自动留城。若返程另需 10 日，先经过返程，再开始累计这些有效休养日。

有效休养日必须同时满足：在己方城市驻留，或在看押城市被合法关押；未作为本场随军人员参加正在进行的战斗；当天开始时粮食库存大于零。行军、押送、随军战斗、断粮时暂停。城外正在交战不暂停城内后方伤兵的恢复，避免敌军靠拖延野战就冻结整座城市的治疗；城市失守后按人员去向重新判断。

城市粮食仍沿用现有月结，不为治疗改成一套新的每日城市扣粮。月底发现欠粮时照常执行短缺处罚，不回滚之前已经完成的恢复；库存为零后暂停后续恢复。这是沿用现行经济时间粒度的取舍。

恢复在全局日流程统一执行一次，以日初已经满足驻留条件的人员为准。当天新抵达、战后新驻留或刚被释放到行程中的人员，不额外领取一次恢复；多战场、月界和存档续算不能重复治疗。

### 调整兵力与经验

- 单将容量按可战兵加伤兵计算，最多 10000。可战 2000、伤兵 3000 时，最多再补 5000 名新兵。
- “调整兵力”仍输入期望的可战人数；界面另列伤兵数和总容量，允许的最大可战人数变为 `10000 - 伤兵`。
- 普通减少配兵只归还可战兵。输入 0 代表归还全部可战兵，不能把伤兵变成可用预备兵。
- 需要解除所部或无兵调任时，在现有配兵流程增加明确的“归还全部所部”选项：可战兵进入同兵种预备兵池，伤兵进入同兵种城市伤兵池。归还操作沿用现有工作点与权限检查；明确解除所部时才取消后续自动归队，不清空伤兵经验。伤兵恢复后仍保留独立来源记录，直到实际补给另一所部时才合并经验；未整编人员继续保留独立记录，不进入可用的普通预备兵池。
- 城市伤兵池不是新建筑，按步兵、弓兵、骑兵汇总展示。自动留城的伤兵在后台保留原所部与经验记录，治疗只汇总人数，不把不同部队的经验静默混合。恢复后，若原将健在、仍属本城势力且驻在本城、未被战斗或出征订单占用，人员已完成所需整编，且有带兵余量，自动归队；否则以同兵种待命兵保留原记录，不跨地图自动补兵。原将被俘、改投别家或死亡，不改变后方人员所属势力，后方仍可将他们调给其他同兵种武将。真正通过配兵、征调、同城自动归队或明确解除所部合并人员时，才按现有规则加权平均经验。自动归队只处理健全且可用的人员，未愈者继续留城。
- 骑兵伤兵只能恢复为骑兵，不能改成步兵或弓兵；配兵、归还、招降和交换均保留兵种。同一武将的可战兵与伤兵必须是同一种基础兵种。
- 补兵、合兵按全部现存人员加权平均经验。例如 3000 名经验 1200 的骑兵伤兵补入 2000 名经验 0 的骑兵，平均经验成为 720，恢复后也不会重新变成原来的精锐。
- 补入可战兵不增加治疗比例，合并伤兵不重置旧伤兵的恢复；人数与经验照常加权保留。一天治疗一次，已经治疗过的人员不能通过换将、分兵、归还或跨城移动再治疗一次。

有伤兵而可战兵为零的武将可以返程、养伤或归还所部，不能发起新的出征。已经回城后再次出征时，原有伤兵自动留在本城的同兵种伤兵池，保留人数与经验，恢复后按前述规则自动归队或作为同兵种待命记录保留，不自动并入普通预备兵的平均经验池。这个留伤兵动作随出征自动执行，不另花工作点，也不要求玩家先手动分兵。预览明确显示“出征可战人数”和“留城伤兵人数”；主动选择出征不等于放弃旧伤兵。

城市生成守方参战编队时，也先把原有伤兵转入本城伤兵池，只让可战兵上阵。城内恢复出的人员保留待命来源记录，不会在战斗中途自动补进棋子。城市失守时，后方伤兵池与城市预备兵按前述无主将人员规则处置；整军撤退只能保住随军人员，不能同时把所有留城库存和伤兵池搬走。撤退确认框必须把这部分城市损失另行列明。

战斗中新增伤兵仍随本次部队返程、驻留或被俘，不在战斗过程中送回后方。第一版不增加伤兵运输订单、逐将伤兵托管或“必须带伤兵出征”的选择。原将回来有余量时可以自动归队，手动补兵也优先使用其同城待命老兵，再使用其他同兵种可用预备兵；预览显示实际经验变化。伤兵留城后不继续占该将带兵容量，也不会自动传送补回远方部队。

## 七 粮耗与短缺

伤兵沿用同兵种正常粮耗，骑兵仍按两倍处理，视为人员与军马整体维持成本。暂不跟踪马匹死亡、装备缴获或治疗费用。

| 人员位置                         | 粮食责任与人数口径                                                     |
| -------------------------------- | ---------------------------------------------------------------------- |
| 己方驻城所部、预备兵和城市伤兵池 | 所在城市供粮；分别按可战、预备兵和伤兵实际驻留兵日计账。               |
| 行军和返程                       | 随军口粮供给，可战兵、伤兵和随行俘虏全部计入。                         |
| 战斗                             | 双方随军粮草承担本方可战兵与随军伤兵；伤兵不能因为棋子消失就停止吃粮。 |
| 入城看押                         | 看押城市供粮；俘虏不计入可用守军，但计入伙食人数。                     |

己方伤兵沿用士兵维持费用，不另收医疗费；俘虏只计粮食，不向其发军饷。人员从战场转到行程、从行程转到城市时，同一天粮耗只能归属一个责任账目。结束战斗时先结清本日尚未收取的战斗口粮，再分配余粮；已经收过则不重收，返程从次日开始计行军粮。不能通过在日推进前手动结束战斗跳过最后一日口粮。

中立城市内的军事人员和俘虏也消耗当地现有库存、执行既有缺粮规则；不因此给中立城市新增势力财政收入或兵饷。前后方分粮预算包括已发生的俘虏兵日与骑兵附加兵日；城市易主时这些旧主责任与普通兵日一并清除，新主从之后的实际驻留重新计账。小部队的定点需求即使不足一整粮，无粮仍算断粮；日末处罚若使尚未结束的战斗击溃或士气溃败，当日结算。

城市预备兵也必须计口粮，归还所部不会让同一批士兵突然免粮；伤兵恢复并归队或成为待命兵后也继续吃粮。现有城市粮耗主要统计守军和所部，纳入预备兵是本次设计需要一起修正的范围。保持原粮耗系数，不在本次同时上调单人费用；界面提供本城军事人员总数、月粮耗估计和可支撑时间，帮助玩家决定补兵、休养或释放俘虏。

同时在现有城市兵源与配兵界面提供“遣散”出口，允许按兵种和数量把未被承诺的在城人员解除编制、归入人口，永久失去相应兵种经验。既可处理预备兵、留城伤兵，也可处理在城所部；不另收金钱或工作点，参战、在途或被订单预留的人员不能用此操作远程抹掉责任。确认框写清损失与粮耗变化。计口粮之后必须允许玩家缩减军队，不能让和平时期的过量征兵成为无法纠正的永久负担。

战后剩余军粮也必须分清去向：胜方自有余粮随本方驻留或返程；败方余粮按结算后逃脱人员与被俘人员的人数比例分给返程方和胜方，全部被俘或无剩余兵员时全归胜方。返程人员存在多个目的地时，再按各行程随行人数分配，整数余数固定分配。突袭中守方留城的剩余军粮归守方。失城守军只能带走这份已计入本方战斗的余粮，不能另从已经易主的城市库存取粮；同一份余粮不能同时加入返程行程和胜方城库。粮食不足不阻止撤退，但返程仍会记录现有行军缺粮，不能免费补足。

断粮不生成伤兵。城市现有月度短缺 15% 减员规则、战斗现有每日 1% 减员及士气处罚继续保留，并覆盖相应账目中的预备兵、待归队人员和伤兵；俘虏承受所在账目的人员短缺损耗，但不产生可作战士气效果。各类人员分别按相同比例减员，报告注明逃亡、死亡等永久损失。

开战不能继续把守城全部库存搬进战场并将城市粮食清零。守方军粮自动按本场最大战斗日数和参战计粮人数预算；后方同时预算本月已发生未结清的驻城粮耗，以及相同天数内留城人员的粮耗。库存够时只划出战斗预算，余粮留城；不足时按前线与后方这两份需求比例分粮，前线向下取整、余数留城。这是自动划拨，没有新增玩家配粮步骤。城市和战斗库存自此分别扣账，不能同时将同一份粮记成可用；真正无粮仍暂停治疗，不能因账目搬家制造假断粮。月度收入仍入城库，不自动变成战场补给。占领时未分配给战场的城库随城易主，不参与败军撤退分粮。

出征补给预估以随军总人数和实际骑兵人数为准。战场伤亡转为伤兵后，仅永久损失者停止消耗口粮，不能把所有战场减员都当作节粮。

## 八 结算示例

### 五千精锐骑兵全部失去战斗力

假设累计战斗减员 5000，伤兵比例 60%，不计本场经验奖励和沿途缺粮。

| 结果                                       | 最终人员去向                                                                     |
| ------------------------------------------ | -------------------------------------------------------------------------------- |
| 其他友军打赢本场                           | 3000 骑兵伤兵保留，2000 永久损失；有粮驻城后逐日恢复。                           |
| 其他友军掩护整军主动撤退，有退路且该将逃脱 | 接战后每将被俘率 5%；逃脱时 3000 骑兵伤兵随将返程，返程结束后再恢复。            |
| 全军被迫溃退，该将抽中逃脱                 | 2000 骑兵伤兵返程；另 1000 失散，总永久损失 3000。                               |
| 该将被俘                                   | 3000 骑兵伤兵随将被俘；看押方养伤供粮，原势力不能使用。                          |
| 被俘后招降成功                             | 招降方得到该将及其现存所部；完成 10 个有效日整编后，已愈者可战，未愈者继续养伤。 |

只要没有混入低经验士兵，这批剩余骑兵不会因为受伤而丢掉精锐身份。战斗结束时可用兵力仍是零，需要回城恢复后才能再出战。

### 单将一万人容量

一名将军有 4000 可战兵和 4000 伤兵，总人数 8000，最多再补 2000。补满后为 6000 可战、4000 伤兵；全部恢复后为 10000 可战，容量不溢出。

两名将军各有 5000 可战兵，在战场临时合并为一个 10000 人编队，不改变各自单将容量。如果两人中一人战后被俘，只移交他自己结算所得的人员。

### 守方主动撤退

征服战中，一名守将本场战后尚有可战 2000、新增伤兵 3000，另有一座可达友城。确认整军撤退后，攻方获得当前城市；该将有 95% 概率带全部 5000 人和分得的剩余军粮去友城，有 5% 概率连同全部 5000 人被俘。逃脱时不再损失随军伤兵。多名守将分别判定，不能因为其中一人被俘就全军被俘。城内战前留存的伤兵池和预备兵不在这 5000 人内，失城时另按城市人员规则处理。若没有可达友城，确认框必须明确说明这会导致整军投降。

### 休养后继续出征

3000 名伤兵首个有效日恢复 300 人，余下 2700 人继续养伤。玩家若急需出兵，可以派这 300 名可战人员出征，原有伤兵自动留城；但这只是 300 人的战斗力，不能在兵力比较中显示成 3000 人。后方人员不参加本场经验分配，也不会因该将被俘而在其他城市一起被俘。

## 九 玩家体验复核

| 场景或问题                         | 本版取舍                                                                                                            |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 判断错兵力，刚开战就想退           | 有路且未接战时可退，损失行程、口粮或城市控制权，不额外抽签扣武将。接战后有序撤退为每将 5%，击溃或士气溃败则为 25%。 |
| 兵多将多反而更容易遇到被俘         | 同时展示每将风险与整军至少一将被俘的风险；保留逐将独立判定，避免一骰决定整军去向。数值先取 5%，不声称已平衡。       |
| 前线伤兵不断加入，恢复期反复归零   | 采用现有伤兵每日 10% 的自动恢复，不维护批次和倒计时；新伤不重置旧伤。大部分人较快归队，尾部恢复慢但不阻止再次出征。 |
| 带一名士兵替大量老兵伤员刷经验     | 经验只奖励实际参战者与本场新伤兵，再按人数合并，不给未参战伤员凭空升级。                                            |
| 每次出征都要手动留伤兵             | 默认自动留城，不新增操作步骤或工作点成本。失城可能损失城内伤兵池，预览明确说明。                                    |
| 友城也在打仗，系统判定全军无路投降 | 可退到可达友城外等待，不因一场临时战斗就把战略退路判为消失；等待期间吃粮、不治疗、不自动增援。                      |
| 战胜后招降精锐，马上用敌兵连续攻城 | 保留整军招降收益，但有 10 日整编；不能通过归还兵池绕过。长期滚雪球仍需观察，不能只靠少量粮耗宣称已解决。            |
| 俘虏太多，想释放却没有回国路线     | 明确提供释放武将并遣散所部的出口，不把处决变成唯一能结束供粮的操作。                                                |
| 没钱粮时只好丢弃辛苦养的精锐       | 不额外收医疗费；伤兵、预备兵和俘虏都在粮耗摘要中可见。允许主动退兵、分配兵力和释放俘虏，代价提前展示。              |

初版不增加单队离场、追击操作、个别伤情、士兵忠诚、马匹装备库存、治疗建筑或批次排队。玩家日常需要做的核心选择只有继续打还是撤、何时再次出征，以及如何处置俘虏；治疗和留后方由系统自动完成。

NPC 也需要使用有序撤退，否则只有玩家能以较低风险保存军队，电脑总打到被迫溃退。第一版只加简单统一策略：在己方行动开始时，若当前可战人数不超过开战人数的 30%，且不超过敌方当前可战人数的一半，同时有合法退路、尚未触发强制结束，则主动整军撤退。玩家托管同样适用，手动指挥不代替玩家做决定。这两个阈值集中配置，留给试玩调整；不增加追击或复杂战略评估。

这些结论来自规则推演与计算，不是人工试玩或战役平衡认证。实现后至少试三种局面：弱方败退后能否组织第二次作战；优势方能否靠招降在短期内无成本连续扩张；多将撤退的损失是否让玩家觉得按钮不值得按。观察结果优先于继续增加惩罚或子系统。

## 十一 后续验收情景

实现时以行为结果验证，不只检查是否新增字段。

1. 5000 人经过普通攻击、反击和计策累计损失到零时，按统一比例留下伤兵；小伤害拆分不改变总比例，已受伤者不能再被攻击。
2. 可战归零但尚有伤兵时，兵种、经验和成长报告保留；士气低于 20 仍与伤兵数量独立。
3. 攻守双方撤退均可确认和取消；有路时未接战无俘虏、接战后每将 5%，无路提前明确投降。友城暂时交战允许城外等待；不把失城直接等同全将被俘。
4. 接战后有序撤退与被迫溃退分别使用 5% 和 25% 被俘率，每将只判一次；预览和取消不抽签，整军风险显示正确。全军击溃或士气溃败已触发时，不能改点撤退覆盖结果。
5. 纯伤兵队伍可以生成、保存、推进和完成返程，不能新出征；守方失城、目的地易手和突袭不占城各有正确去向。
6. 在仅有该批伤兵、无断粮或转移时，3000 伤兵首日恢复 300 人、约第 22 个有效日恢复九成；新增伤兵不重置治疗。全城按兵种汇总取整，拆分、移动或读档不能多恢复；原有伤兵留城可治，本场随军伤兵不可战中治疗。
7. 可战 6000 加伤兵 4000 时不能再补兵；新出征自动留伤兵不额外花工作点。留城记录保留原所部经验，同城合法归队不溢出容量、不抢占预留兵源，也不跨城传送或重复计兵。
8. 所部、预备兵、待归队老兵、伤兵和俘虏都按所在责任账目吃粮，骑兵为两倍；整编和伤兵不提供即时可用兵力。归还、恢复或押送不重复计粮，玩家可遣散未承诺的在城人员以缩减负担。
9. 招降后 10 个有效日内所部不能出征、参战、供留守或征调，换将、分兵和归还不能绕过；释放、交换、获救不重复罚整编，既有未完成限制也不被洗掉。无返乡路线仍可通过明确的释放并遣散出口结束看押。
10. 全程人员守恒：随军和留城人员合计，等于本方现存人员、被俘、永久损失及明确遣散人员之和；人口回流只记一次。实际参战者与本场新伤兵获奖，战前伤员和后方待命者不靠少量参战兵刷经验。
11. NPC、自治太守和玩家使用相同规则；战斗中途、战后返程、押送与月界续算均可正确存读档，报告保留当时快照。
12. 征兵选定的兵种经由预备兵、单将所部、伤兵、俘虏和恢复全程保持不变；不同兵种不能混入同一武将所部，也不能跨兵种合并经验或补兵。
13. 战后双方剩余粮食等于各城市与行程接收的粮食总和，加明确记录的容量溢出损失；多人部分被俘、守方主动撤退失城、突袭守方留城和多目的地返程都不重复记粮，也不凭空补粮。

14. 后方有粮且符合休养条件时，城外开战不因抽空城市库存而冻结治疗；最后一个战斗日通过手动操作结束和通过日推进结束，供粮各执行一次。
15. 空城、仅有伤兵或仅有整编部队时不生成免费民兵；非参战武将失城后有真实去向，预备兵不被自动当成野战兵。守方撤离和释放路线按行军方而非城主计算。
16. 招降或交换失败后仍可释放；双方交换次数正确扣除，押送中不能调用入城处置；NPC 与玩家托管能在满足简单条件时有序撤退。
17. 正常人员与未整编人员不能合并后一起解锁或一起被冻结；同一将军多次留下不同经验的伤兵可以有多条合法记录，记录 ID 和人数不能重复。满城容量下必须明确处置溢出的粮食或人口，不能因悄悄截断数据让守恒验收失真。

实施顺序以[伤兵机制实施计划](10-wounded-system-implementation-plan.md)为准：先确定来源、每日与路线契约，将存档与共享查询放进 W1，再接战斗、战后去向、恢复粮耗、俘虏与 NPC、界面和全流程验证。各步可以分别验证，但在去向、口粮和存档闭合前，不作为可玩的伤兵功能发布。
