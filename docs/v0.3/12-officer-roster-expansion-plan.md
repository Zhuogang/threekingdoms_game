## 年代与人物状态

### 登场年龄

统一以 16 岁虚岁作为普通武将的可用年龄下限：年龄按“当前年份 − 生年 + 1”计算，年龄下限对应“生年 + 15”。这一口径允许现有 190 年孙策、周瑜一类年轻人物继续出现，但原有年龄数据也必须逐项核对，不能把旧种子里的年龄直接当作史实。

每个人单独配置实际登场年，不能统一套用“生年 + 15”作为最终年份。16 岁虚岁只是玩法下限；实际登场年还要结合当年生活、活动地域及可核记录决定，并满足不早于年龄下限。童年轶事不等于已经可以任官或领军。

出生、实际登场、开始效力某势力是三件事。已经成年且合理处于当地的在野人物可以被玩家提前于其史实投主年份招募；不能因此把尚未到实际登场年的人放入搜索池。史料只能确定范围时，记录范围、选定的策划年份及近似标记，不把计算下限冒充史实出仕年份。

按用户补充，史料没有记载的生卒及早期登场优先参考《三国志11》，必要时补查《三国志10》，逐字段标记“游戏参考”并保存来源，不能冒称史实。本次 98 人均有《三国志11》对应条目。参考登场早于本作 16 岁虚岁下限时顺延；有明确史料的生卒不被游戏值覆盖。史料与游戏都不能给出参考时才保留 `null`、显示“不详”，年度增长与 18 岁成长跳过未知年龄。不能从头像的年龄感倒推生年。

45 位新增者和原有 53 位都要经过同一轮时序核对。已有 `DECEASED` 名单只是剧本数据，也要核对依据；生卒不详或存在争议时保留说明，不把推测写成确证。没有可靠卒年时可按已标明来源的游戏参考卒年配置开局存亡；这属于玩法设定。若两者均无依据则不判死，不能把失去记载等同于死亡。

18 岁成长要采用同一能力基准：人物库保存成年基准，已知未满 18 岁者的起值按既有成长幅度下调，到 18 岁只把该差额加回当前值；成年开局不再额外加一次。不能直接覆盖成年数值，抹去已经获得的训练、等级或装备收益，也不能因成长事件把精良兵器提供的合法加成压低。生年不详但已有成年活动依据者使用成年基准、年龄显示不详。R1 必须列出原有数值的校准差异；排除游戏内训练、装备等变化后，190 年自然长到 200 年和直接开局 200 年应采用相同的年龄与基础成长口径。

### 剧本开局

开局分为三类：

- 已达到登场条件且在世：创建正常人物，明确其在职势力或在野城市。
- 尚未出生或尚未达到登场条件：只在人物库和待登场安排中存在，不进入世界中的武将列表。
- 按史料或标明的游戏参考在开局以前已故：保留不可用的死亡记录，不能搜索、任官、出战或成为继任者。

剧本按该年一月一日开局。只有死亡年份时，上一年或更早去世者判为开局已故；当年去世不直接当作开局前已故。最后的各状态数量在逐人年表确定后生成，不沿用原来的 52/53 人计数。

本轮时序精度为年份，不把史料的农历月日硬换算进每月固定 30 天的游戏日历。同一年发生的投奔、继位等事件按开局前后分别核定，不能把整年的最终结果当作一月一日的状态。

### 开局归属与地点

新增者的“魏、蜀、吴、群”头像分类不决定剧本所属。按开局时点逐人处理：

1. 当时已经服务于本剧本存在的势力，直接配置为在职，不能为了让玩家搜索而全部改成在野。
2. 当时尚未出仕或归属无法确定，配置为有据可解释的在野人物。
3. 原本属于本轮没有建模的独立势力，采用六势力剧本的抽象安排：作为地方人物供招募，资料明确说明“原势力未独立建模”。游戏所属为空，不伪称其史实上无主，也不创建一个没有城池的隐藏势力。

例如，200 年开局的郭嘉应在曹操阵营，张昭在孙策阵营；许攸不能因为官渡之战后来转投曹操就提前归曹。参见[郭嘉传](https://zh.wikisource.org/zh/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B714)、[张昭传](https://zh.wikisource.org/wiki/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B752)、[许攸相关记载](https://zh.wikisource.org/wiki/%E4%B8%89%E5%9C%8B%E5%BF%97/%E5%8D%B712)。本轮不强制重演此后的投奔，也不自动改换忠诚和所属。

刘表、公孙瓒、袁术、陶谦、孔融、张鲁等逐年核对存亡后，按第三类安排；到开局前已故者仍不可用，不能用“原势力没建模”使其复活。现有六势力版图保留其玩法抽象，不宣称本轮已经复原完整政治版图。

落点优先采用当年的活动或生活地，其次才是籍贯的近似映射，不能用晚年战场倒推少年所在地。最终每剧本、每人物必须确定唯一有效城市 ID；“荆州”“江东”等候选区域不能进入运行数据。开局在职者应位于其所属势力的有效城池；若当前版图无法容纳合理安排，R1 列出具体调整，不能让人物被错误地当作驻敌城臣属。

### 游戏中的未来登场

未来人物到登场年时，在配置城市以在野、零兵、零伤兵、零经验、零整编天数出现。城市已经易主时仍为在野，当前城主不会自动获得人物；通过正常搜索招募。人物也不会直接带入人口、预备兵或粮食。

年度登场放在现有年界月结及旧人物增龄完成之后、交还玩家控制之前，不重排现有粮耗、自治及月事件。新人不补领该轮已经结束的自治行动，下轮起参与正常自治搜索。新登场者按当前年份计算年龄，避免刚以 16 岁出现又被同一轮处理加到 17 岁。开局直接创建的可用人物也不额外触发一次年初增长。

同一人物只登场一次：已存在的在职、在野、行军、战斗、被俘、已故记录都不能再次生成。年度登场使用固定的 ID 顺序，不额外消耗随机数；新增搜索等实际游戏行为仍可改变后续随机序列，不要求新版回放等于旧版结果。推进一日、一旬、到事件或保存后重载都要得到一致结果；同年的消息合并为一份人才消息。

被围城也允许人物进入在野记录，但遵守本城已承诺状态，不能立刻搜索或编兵；人物不会自动加入正在进行的战斗。无主城必须区分“民兵／参战人员”和“同城在野人物”，不能用 `null === null` 将在野者当作守方并在城池易主时判俘。零兵在职将仍按现有撤退与判俘规则处理，两者不能混淆。

本轮是固定历史人物名单，不模拟婚育；待登场安排不因游戏里父母的去向重新计算。此抽象需在玩法说明中讲清楚，不增加隐含的生育或血缘继承规则。

### 生卒年的使用范围

已确认：生卒用于核对剧本开局的人物存亡，开局后由游戏决定命运。不按史实去世年自动移除人物，也不强制重演其战死、被杀或病逝。玩家保住的人物可以继续使用；游戏里已经死亡或被处决的人物也不会因登场表再次复活。

存活且已登场者正常增龄；已故记录的年龄冻结，不继续增长或触发 18 岁成长。开局已故者有可靠生卒时按去世时年龄建立记录，资料不详时显示不详。

## 数值与开局平衡

继续使用武力、智力、忠诚、个人经验、个人等级及一个基础兵种。谋士不必都设为弓兵，文官也能领兵，但武力与智力的分工要清楚。少数顶尖人物进入 90 以上的强项区间，99–100 保持稀缺；现有武将数值以复核后的基线为参照，不因扩容普遍抬高能力。

新增武将默认零兵。即使史实安排为开局在职，也不能走现有 `700 + index % 4 × 100` 的通用配兵公式。新将使用同兵种预备兵编兵或正常征募；如确需开局带兵，应从该城既有兵力内重分配，并明确来源。

扩容前后逐城、逐势力核对健康兵、伤兵、预备兵、人口、粮食和金钱。不把新增人物自动变成免费军队，不给在野或未登场者计算驻城在职人数。城市工作点仍最多三点；若按年代校正使某城少一名可用人员，要记录其工作点变化。

太守、君主、首都及原有兵力使用明确配置，不依赖人物数组顺序。原有君主若因出生或生卒审核不再适用于某个开局，先调整剧本设计，不让初始化随意选出另一人。

## 人物库与技术改动

### 人物定义和剧本安排分离

计划新增统一人物定义模块，保存 98 个稳定 ID、中英文姓名、复姓、基础能力、唯一兵种、生卒依据、年龄是否已知及头像引用。两个剧本各自保存开局归属、城市、职务、存亡及未来登场安排；头像分类不参与决定所属势力。

建议将基础定义置于 `content/officer-catalog.ts`，年代及年龄计算置于 `content/officer-timeline.ts`，开局安排由两个剧本各自引用。`officerIdentity.ts` 保留现有接口并从同一份定义派生身份，避免姓名、复姓及人物 ID 在多处手工维护。

保留现有 ID 的别名关系：马腾的游戏 ID 为 `maliang`，其资源规范 ID 为 `mateng`；新增马良使用 `maliang_shu`。祖茂的游戏 ID 为 `zuzhao`，资源规范 ID 为 `zumao`。此轮不同时重命名这些已被剧本、军队和报告引用的 ID。

### 待登场安排与世界状态

`state.officers` 继续只保存已经进入世界的人物及其死亡记录。待登场者保存在剧本的静态登场安排中，不创建一个 `alive: true` 的少年对象后再要求所有搜索、任官、外交、战斗、俘虏、继任和粮耗代码额外过滤。

年界处理从登场安排中找出到年的 ID，在世界中尚无该 ID 时创建人物。已有死亡记录也算已经出现，不能重新生成。人物年龄由生年和当前年份计算；生年不详的年龄为 `null`，相关类型、存储校验和年度事件一起适配。

保存一个已处理登场年份标记 `lastOfficerDebutYear`，开局置为剧本年；只处理它之后至当前年的既定日程，而不是遍历整个名册给所有缺失 ID 补人。人物、消息与标记原子提交；重复处理已完成年份直接跳过。读取时按开局名单和已处理日程校验应有 ID，缺失的既有人物记录应报无效存档，不能当作尚未登场重新生成。

新战役使用完整安排，并在世界状态和存储校验中绑定名册版本，使用 `officerRosterVersion: 1`。该标记同时绑定本轮人物与登场安排的内容版本；修改时序表后必须同步升级，不能只保持相同数据形状就静默套用另一版日程。这也避免只存有旧 53 人的战役在下一年界意外混入新规则。正常新存档必须能导出、导入及续玩；沿用此前不做旧档补全或迁移的范围，旧名册需要新开战役，不自动补人。

人物创建、同年人才消息及月度工作计数一起提交和保存。规划与执行分离时，应重新校验城市归属、人物状态、库存预留和剩余工作点；过期计划拒绝执行且不发兵、不扣点。原有人物与死亡记录不从列表物理删除，作为防止重复出现的依据。

### 搜索招募与编兵

搜索保持本地随机抽选，每次有候选人的尝试消耗一个城市工作点；成功率沿用 `40 + floor(执行者智力 / 2)`%，本轮不改成指定人物必中。空候选池应在共享资格检查中禁用，不消耗工作点。名册能查看某人，不代表已经加入或能够点击姓名直接定向招募。

未登场者不在搜索池；在野者按实际城市参加搜索；在职、已故、被俘、行军或在战者不能作为新人才再次招募。成功后按既有方式设置归属和初始忠诚，仍为零兵，不同时触发任官、迁城、赠兵或升级。任何合法势力都可以招募，不按人物后来的魏蜀吴身份锁定。

玩家继续只直接办理君主本城的城务。外城的人才由当地自治搜索；玩家查看其详情时应显示权限原因和现有调任／出征路径，不显示一个实际会被拒绝的“直接招募／编兵”按钮。不能把跨城看图鉴变成跨城调兵权限。

### NPC 首都和地方城市

现有月度自治跳过 `governanceMode === ruler` 的城市，主动城务又只授权玩家本城。只改太守自治不足以让 NPC 首都招募、编兵。本轮必须给 NPC 君主本城补齐受同样工作点、库存与承诺约束的内部执行路径；由势力当前首都定位，不能依赖玩家正在查看的城市。

该路径必须验证执行势力与城市主人，拒绝玩家直接指定敌城或以自动执行标志绕过权限。地方城市继续走既有自治；按城市、月份共享工作点和人才行动计数，避免首都迁移、重复月结或两个规划器重复发行动。

城市每月仍最多三点；搜索失败也消耗已执行的这一次工作点。自动工作每城每月最多一次人才搜索、一次首次编兵，分别记在按月重置的计数中；不能用 `workUsed === 0` 假装记住是否做过某类工作，也不能从日志解析计数。手动搜索仍可在现有工作点范围内多次尝试，不被自动工作的“一次”限制误伤。

### 零兵将的首次编兵

首次自动编兵只选同城本方、存活、未被承诺、无健康兵也无伤兵、整编已结束的武将。按武力与智力合计降序、再按 ID 排序选一人；不强制选择太守，也不把健康兵为零的伤兵部队当作新将重置。

目标最多 500 人，允许按同兵种的可支配余量编入 100–500 人；不足 100 人暂缓。100 人仅是自动首次编兵的策略下限，不改变玩家现有编兵或战斗人数范围。每城每月最多一次，不因先归还再编入反复触发。500 不再是必须攒齐的门槛，避免低产的骑兵长期无法起兵。

同兵种余量不足时，可以先针对选中武将的兵种正常征募，再用剩余工作点或下月编兵。征兵数量和费用由既有规则计算，显式传递目标兵种，不能继续只按太守的兵种征兵；也不能将步兵库存直接当成骑兵。

要区分城务执行者和受兵目标：征募时，执行者负责提供既有能力加成，兵种取待编将领的兵种；编兵时，受兵目标才是该零兵将。不能为了换兵种误换执行者，或把最终兵数误当作新增兵数。两步分别消耗各自工作点，不能合并成一次免费的征募加编兵。

优先级收敛为：粮草、治安和留守等紧急事项先处理；没有紧急事项时，先使现有零兵将可用，再搜索新人才，普通宴饮、训练和建设排在人才任务之后。忠诚过低的紧急安抚仍可优先。军资不足时跳过不可执行的方案，不反复选择一个失败操作耗尽流程。

使用同一资格检查和编兵命令：扣除真实同兵种预备兵，保留其经验，更新驻军与未来粮耗，保护已批准订单、留守、健康兵加伤兵一万人的上限及整编约束。编兵不是征兵，不增加人口或士兵总数。战略 AI 仍按既有最多十将、出征留守与行军粮草规则选队。

可检查的完成条件是：成功招到人后，在没有紧急事务、有预算、同兵种预备兵及口粮充足的连续两个正常月结内，至少让一名合格零兵将获得可用兵力；NPC 首都与地方城市分别验证，不以“AI 名册增加了一个人”代替验收。

### 头像与人物界面

统一按头像清单中的实际文件路径解析 128px/256px 资源，不再把所有人的头像都拼成 `assets/portraits/...`。更新战场统帅头像、侧栏、开始页及人物详情；新增人物卡使用复姓和姓名占位，缺图不影响按钮及操作。

从资源清单生成仅含 ID 和两档路径的小型运行索引。完整提示词、高清来源及生成记录继续留在资源文档中，不将这份较大的制作清单直接打进游戏包。

16 套旧人物修订像不是额外人物。早期剧本继续保留适龄的原图；修订像的启用要明确版本适用条件。新人物固定头像的年龄感不能改变其生年或登场年。本轮不引入逐年换脸，也不重新生成全部美术。

城池列表区分在职与在野，不能把未加入者当成己方将领。人物名册可显示 98 人的“未登场／在野／在职／被俘／已故”与登场年份，未来人物只显示资料，不能进入现役操作页。已故人物不能因查看头像而触发重新创建。

中英文都需验证，尤其司马、诸葛、公孙等复姓。更新汉字字体子集，覆盖祎、叡、恪等新增姓名字；小头像按实际可见人员加载，不一次解码全部 196 张图片。

新增人物的楼船展示资格按个人名单明确配置，不因属于吴阵营自动获得。继续由同一统帅决定头像和船型，不改变上下水与水战倍率。仅使用当前已经实际接通的特性机制；不能把旧特性说明中未实现的效果顺便当作新功能发布。

## 测试与验收

### 人物数据

- 98 个唯一人物 ID 与头像清单一一对应；新增者恰好 45 人，旧 16 套修订像不增加人数。
- 两剧本均有六个合法势力，所有开局城市和未来落点属于现有 24 城；每个君主、太守及首都引用有效。
- 已知生年、卒年、登场年顺序合理；16 岁虚岁边界正确，年龄不详不会触发虚假的成年成长。
- 年龄下限和实际登场年分别校验；有可靠生卒时，不允许实际登场年晚于已知卒年。资料有争议的具体年份必须带依据和近似标记。
- 开局在职、在野、已故和待登场恰好覆盖 98 人；核对郭嘉、张昭、许攸一类存在既有效力关系或同年转投的人物，不能全部塞入在野池。
- 马腾与马良、祖茂别名、复姓、中文姓名及英文名无串用。

### 年界与人物状态

- 190/200 开局之前已故者不可用；未出生和未到年龄的人不进入搜索、任官、继承、部队或粮耗统计。
- 检查登场年前一天、当年一月一日和次日；存活旧将只增龄一次，新将仍为正确登场年龄，已故年龄冻结。
- 单日、跨旬、跨年、存取档、重复处理边界均只生成一次人物和一次消息。
- 人物已在野、已招募、被俘、在途、在战、被处决或已死亡时，都不能重复出现。
- 出生地易主或相关旧势力被灭，未来人物仍按有效城市以在野身份出现，不自动入仕城主。
- 在合法的能力变化之外，190 年推进至 200 年与直接开局 200 年的年龄和成年成长一致；已有训练、等级、装备加成不被覆盖或降低。
- 在野者不因无主城的空势力比较被当作守将判俘；围城中新出现的人不被插进已生成的战场或被追溯计算参战状态。

### 可玩性与兵员

- 搜索成功后真实改变归属；失败消耗沿用现有规则；玩家和 NPC 都能获得与使用新人物。
- 招募不赠兵；新将零兵不能出征。编兵扣除正确兵种的预备兵、保留经验，不挪用伤兵或已预留兵力。
- 新人物能走完任官、出征、受伤、撤退、被俘、释放／招降、整编和恢复流程。
- 超过十位带兵武将时依旧遵守编队与民兵上限，合并后统帅头像、兵种、经验和楼船展示一致。
- 对各势力进行固定种子的机器回放，记录新将招募和实际编兵；不把“数据库中有这人”作为可玩性验收。
